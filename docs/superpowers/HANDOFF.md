### 0-2. 段階 ① の作り（次に触る人へ）

- **生成の流れ**: アプリ →（関数 `studio` の `startJob`）→ チケットを引くのと仕事を作るのを 1 つの取り引きで → 列（Cloud Tasks）に入れる → 列が関数 `studioWork` を呼ぶ → `tools/cloud/studioCore.ts` の `workJob` → `runJob` が 1 点ずつ作り、**できたらその場で自分の服として保存**（候補は `kept`、服の ID は `my:{仕事}-{番号}-{取りかかった回数}`）。アプリは「進める」を呼ばない（聞くだけ）。
- **必ず「服か払い戻し」で終わる守り**: 失敗は「`failed`・`refunded: false` と書く → 払い戻す（`refundOnce`）→ `refunded: true`」の順（`settleRefunds` が、何度でも安全にやり直せる）。1 品目に取りかかれるのは 3 回まで。ほかの呼び出しが進めていたら `'busy'` を返して 60 秒あとに列へ。聞かれたとき（`job`・`jobs`）と、1 時間に 1 回の見回り（関数 `studioSweep`）が `tendJob` を呼び、止まった仕事を列に入れ直す（列に入れられなかったと分かっている仕事 = `queueFailed` は 30 秒おき、列に入れてあるはずの仕事は 5 分たってから）・24 時間たった仕事を打ち切る。
- **取り引きの中身は、何度呼ばれてもよいように書く**: Firestore は、確定の返事が届かなかった取り引きを、もう一度呼ぶ（前の回が確定していることがある）。`runJob` の受け持つ・結果を書く、`tendJob` の入れ直し、`chargeAndCreateJob` は、「もう書いてある」を見分ける。`studioCore.test.ts` の `replayTransactions`（どの書き換えも、確定のあとにもう一度呼ぶ）で確かめている。ここを直すときは、このテストを足すこと。
- **アプリの側**: `src/cloud/session.ts`（つなぎ役。ページに 1 つ。`src/cloud/boot.ts` が作る）が、つなぐ・服を端末に合わせる・作りかけを聞く（つくる・クローゼットを開いている間は 3 秒おき、ほかは 30 秒おき、見えていない間は聞かない）・届いた仕事（`arrivals`）・NEW の印を持つ。画面は `useSyncExternalStore` で見る。「つくる」を教えていない端末（`readStudioMode()` が null）は、`boot` も Firebase も読み込まない。

## 7. 開発環境の注意

- 依存の導入: `npm ci`
- ユニットテスト: `npx vitest run`　型: `npx tsc -b`　lint: `npx eslint .`
- E2E: `npm run build` のあと `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test --trace off`（クラウド環境では、導入済みの Chromium を使うためにこの環境変数が必要）。
- エミュレーターのテスト: `npm run firebase:test`（関数をまとめ、Firebase のエミュレーターを起動して `functions/test/*.emu.ts` を走らせる。Java が要る。初回は、エミュレーターの本体をダウンロードする。クラウド環境で動く。1 分ほど）。ふだんの `npx vitest run` には入っていない。
- E2E の `appStudioReal.spec.ts` は、Firebase 宛ての通信を全部受け止めて偽の返事を返す（本物のプロジェクトに、テストの利用者を作らない）。`?studio=1` を開く E2E を足すときは、必ず同じ受け止め（`fakeFirebase`）を使う。
- クラウド環境は、このリポジトリ用の環境「DressUpGame」を使う（公開サイトと Gemini を開ける。開始時に `npm ci` と、隣への素材リポジトリの取得を自動で行う）。**隣の素材リポジトリは古いことがある**ので、最初に `git -C ../DressUpGame-content pull --ff-only` する（2026-11-20 のセッションでは 3 コミット古かった）。
- 素材リポジトリへ push するには、セッションに `Kake-git-hub/DressUpGame-content` を追加する必要がある（読むだけなら不要）。
- 画像生成を呼ぶとき: `NODE_USE_ENV_PROXY=1 GEMINI_API_KEY=dummy`（中継がキーを差し込む）。例: `STYLE_ID=anime NODE_USE_ENV_PROXY=1 GEMINI_API_KEY=dummy npx tsx tools/studio/tryItems.ts ../DressUpGame-content <ドールの ID> <品目の JSON> <出力フォルダ>`。処理だけを直して確かめるときは、出力フォルダの `raw-N.png` を `STUDIO_FAKE_IMAGE` に渡す（生成しない）。
- 実物の素材でゲームを見る: 素材フォルダの `manifest.json` と `files/` を `dist/real-content` にコピーし、`npx vite preview --port 4173` で `/DressUpGame/?content=real-content/` を開く（`?content=` は同じオリジンの相対パスだけ受け付ける）。
- スタジオを実物の素材で見る: 素材フォルダの `manifest.json`・`files/`・`studio/` を別のフォルダにコピーし、`CONTENT_DIR=<そのフォルダ> npx vite --config vite.studio.config.ts --port 5199 --open false` で `/DressUpGame/studio.html` を開く。
