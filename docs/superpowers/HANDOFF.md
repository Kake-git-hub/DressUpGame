作者が決めたこと: サーバーは Firebase（Blaze に切り替える前提）。生成も画像の処理もサーバー側。「つくる」は保護者（大人）が使う画面として分け、入口で確かめる（Gemini の利用の決まりが、18 歳未満向けのアプリでの利用を禁じているため。この分け方で足りるかは、販売の前に Google か専門家に確かめる）。服ごとの利用者の制限は、公開の素材では作らず、サーバーで「特定の利用者に届ける」として作る。

段階 A で作者に見てもらうこと: iPad のホーム画面から開いて、上のバーとの重なりが直ったか。**直っていない見込みもある**ので、直っていなければ、画面の写真をもらう（何が重なっているかは、こちらでは見えていない）。v0.21.2 でも、メニューと右のボタンは「端末が教える上の高さ」をあけていた。v0.22.0 で確実に変わるのは、調整画面の右上のボタン（上のバーの分だけ下がる）と版数の位置。メニューと右のボタンは、端末が 24px より小さい値（0 など）を教えるときだけ下がる。キャンバス（背景とドール）の位置は変えていないので、背景は上のバーの下まで描かれる。

段階 B で作者に見てもらうこと: iPad で、調整画面の左の一覧の絵を指でつかんで上下に動かしたときの手ざわり（動き始め、離したときの入り方）。服をたくさん着たとき（一覧が画面に収まらないとき。iPad の横で 9 点くらいから）は、動きが変わる: すばやくなぞると一覧が流れ、絵を長く押してから（0.25 秒。絵が浮く）動かすと並べ替え。浮かせた絵を一覧の端へ持っていくと、一覧が流れ続ける（こちらでは、指での操作はまねた入力でしか確かめていない）。

段階 C で作者に見てもらうこと: iPad とスマホを縦に持って、(1) 服を上へドラッグして着せられるか（服の行を出たところから、絵が指に付いてくる）、服がたくさんあるカテゴリで行を横になぞって流せるか（はっきり横に動かしたときだけ流れる。斜めならドラッグ）、(2) 持ち替えたときに服がずれないか、(3) 更新の前に調整していた服装が、同じ位置で出るか、(4) 縦の調整画面（一覧を左右に動かす、色、↺・✓）、(5) スマホでは背景の正方形が小さめ（画面の幅）で、下が服の行 3 段になる。これでよいか。こちらでは、実機の指の操作と、ホーム画面から開いたときの上下のあき（時計の表示・ホームの線）は確かめられていない。

段階 E1（v0.26.0）で作者に見てもらうこと: Safari では `https://kake-git-hub.github.io/DressUpGame/?studio=fake` を開く（その端末にだけ「✨」が出るようになる。消すときは `?studio=0`）。**ホーム画面に置いたアプリでは、右上の版数を 5 回続けて押し、あいことば `fake` を入れる**（消すときは `off`。本物につないだあとは `studio`。ホーム画面のアプリは Safari と保存が別で、URL では出せないため。実機で出せるかは、こちらでは確かめられていない）。保護者の確認は、開くたびに毎回たずねる（大人が開いたあと、子どもがそのまま開けないように。こちらの判断で、設計の「閉じるまで覚える」から変えた）。保護者の確認の画面と、服を作る画面の流れ・言葉・分かりやすさを見てもらう。**確認用なので、絵は色の四角で、AI は使わない。チケットも端末の中だけのにせもの**（残りを戻すには、端末の Safari の設定からこのサイトのデータを消す）。作った「自分の服」は、その端末にだけ残る。

縦画面の作り（次に触る人へ）: 描画の計算は変えていない。縦では、キャンバスそのものを「画面の幅 × 正方形の一辺」にして上に置き、メニューの幅・右のボタンの幅を 0 で渡している（`src/components/layout.ts` の `computeLayout`）。服の位置の調整値は、状態と保存では「ドールの絵の px」、描画と調整画面に渡す直前に「キャンバスの px」に直す（`src/engine/units.ts`、`App.tsx` の `canvasItems`）。

## 2. 進行中: 「アニメ」を「アニメ　その２」にまとめる（作者の方針、2026-11-20）

作者は、「アニメ」の服を全部「アニメ　その２」に移し、「アニメ」を消すつもり。

- **済んだこと**: 「アニメ」の服 102 点を、そのままの位置で「アニメ　その２」にも置いた（`npm run content:fix -- copy-items`。絵のファイルは共有。「アニメ」は消していない）。公開済み。着せた一覧の絵: `docs/superpowers/specs/2026-11-20-merge-anime/`（カテゴリごと）。
- **合い具合**: 体の服（トップス・ボトムス・ドレスなど）は、おおむね合う。頭まわり（かお・ヘアスタイル・ぼうし）は、「アニメ　その２」の頭のほうが大きいので、小さく見える（頭のふちがはみ出す）。くつは、足の向きが違うので、足先がはみ出す。
- **次**: 作者が、要らない服をスタジオの「一覧」で消す。そのあと、作者の指示で「アニメ」を消す（まだ消さない。消す道具は無い。スタジオにはドールを消すボタンが無いので、作るか、一覧ファイルを道具で直す）。頭まわりを新しい頭の大きさに合わせて置き直す処理は、作者に提案済み（返事待ち）。
- 名前が同じ服が 3 組ある（もこもこパーカー、きらきらおめめ、きらきらがらすのくつ）。ID の末尾に `-2` が付く。

**作者の PC のスタジオに「アニメ　その２」「おとこのこ」が出なかった件**（2026-11-20）。原因は、PC の素材フォルダに未公開の変更（アニメ 102 → 93 点、リアル 11 → 10 点への削除）が残っていて、公開済みの 7 件を取り込めなかったこと（作者の画面の写真で確かめた。v0.21.1 で足した「版数」と「素材の取り込み: …」の表示が役に立った）。v0.21.2 で、未公開の変更を残したまま取り込むようにした（`tools/content/merge3.ts`、`StudioApi.pullKeepingLocalChanges`）。同じ状況を手元で再現して確かめたが、**作者の PC で直ったかは、まだ聞いていない**。

このとき分かったこと: スタジオは開発用の設定（React の StrictMode）で動くので、画面を開いたときの処理が 2 回同時に走る。取り込みは、サーバーでも画面でも「同時には 1 回だけ」にしてある（E2E が 2 回に 1 回落ちたのは、これが原因だった）。スタジオの画面を開いたときに走る処理を足すときは、2 回同時に走っても困らないようにすること。

## 5. 作業の決まり（このプロジェクトで続けてきたやり方）

- **作者への報告は日本語**。専門用語を避け、数値と「確かめられていないこと」を必ず書く。
- **テストを先に書く**。失敗を見てから実装する。本物の生成画像で起きた不具合は、その絵を見本（`tools/studio/fixtures/`）にしてテストに残す。
- 大きな変更は、計画を書いて作者の了承を得てから実装する。作者が具体的に指示した変更は、そのまま実装し、設計と結果を `specs/` に残す。最後に、別の目（サブエージェント）の全体レビューを 1 回かける（v0.21.0 は、利用の上限でレビューが途中で止まり、自分での見直しだけ）。
- **ドールの形や下着を変えるときは、先に作者に確かめる**（男の子の下着を、こちらの判断で決めて作り直しになった）。体の位置が同じなら、絵だけを差し替えれば服は作り直さなくてよい（`makeDoll.ts replace`）。形が変わったら、その部分にかかる服は作り直す。
- **`main` へのマージ**: 作者の指示（2026-11-19）は「作業が終わったら、毎回そのまま `main` にマージして push する」。ただし、クラウドのセッションには「決められた作業ブランチ以外へは、その場の明示の許可なしに push しない」という決まりがあるので、セッションごとに作者に一度確かめる。テスト（ユニット・E2E）・型・lint が通ってからマージする。`main` に入ると GitHub Actions が自動で公開する。
- **push 済みのコミットは書き換えない**（force push は拒否される）。
- 版数は `src/version.ts` の `APP_VERSION` と `README.md` の両方を上げる（ゲームとスタジオの両方に出る）。
- iPad 実機でしか確かめられないことは、確認項目として作者に渡す。

## 7. 開発環境の注意

- 依存の導入: `npm ci`
- ユニットテスト: `npx vitest run`　型: `npx tsc -b`　lint: `npx eslint .`
- E2E: `npm run build` のあと `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test --trace off`（クラウド環境では、導入済みの Chromium を使うためにこの環境変数が必要）。
- エミュレーターのテスト: `npm run firebase:test`（関数をまとめ、Firebase のエミュレーターを起動して `functions/test/*.emu.ts` を走らせる。Java が要る。初回は、エミュレーターの本体をダウンロードする。クラウド環境で動く。1 分ほど）。ふだんの `npx vitest run` には入っていない。
- E2E の `appStudioReal.spec.ts` は、Firebase 宛ての通信を全部受け止めて偽の返事を返す（本物のプロジェクトに、テストの利用者を作らない）。`?studio=1` を開く E2E を足すときは、必ず同じ受け止め（`fakeFirebase`）を使う。
- クラウド環境は、このリポジトリ用の環境「DressUpGame」を使う（公開サイトと Gemini を開ける。開始時に `npm ci` と、隣への素材リポジトリの取得を自動で行う）。**隣の素材リポジトリは古いことがある**ので、最初に `git -C ../DressUpGame-content pull --ff-only` する（2026-11-20 のセッションでは 3 コミット古かった）。
- 素材リポジトリへ push するには、セッションに `Kake-git-hub/DressUpGame-content` を追加する必要がある（読むだけなら不要）。
- 画像生成を呼ぶとき: `NODE_USE_ENV_PROXY=1 GEMINI_API_KEY=dummy`（中継がキーを差し込む）。例: `STYLE_ID=anime NODE_USE_ENV_PROXY=1 GEMINI_API_KEY=dummy npx tsx tools/studio/tryItems.ts ../DressUpGame-content <ドールの ID> <品目の JSON> <出力フォルダ>`。処理だけを直して確かめるときは、出力フォルダの `raw-N.png` を `STUDIO_FAKE_IMAGE` に渡す（生成しない）。
- 実物の素材でゲームを見る: 素材フォルダの `manifest.json` と `files/` を `dist/real-content` にコピーし、`npx vite preview --port 4173` で `/DressUpGame/?content=real-content/` を開く（`?content=` は同じオリジンの相対パスだけ受け付ける）。
- スタジオを実物の素材で見る: 素材フォルダの `manifest.json`・`files/`・`studio/` を別のフォルダにコピーし、`CONTENT_DIR=<そのフォルダ> npx vite --config vite.studio.config.ts --port 5199 --open false` で `/DressUpGame/studio.html` を開く。
