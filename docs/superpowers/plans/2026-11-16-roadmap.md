# きせかえゲーム改修 ロードマップ

**設計書:** `docs/superpowers/specs/2026-11-15-lightweight-rework-design.md`

設計書は 7 つの独立した段階に分かれる。段階ごとに 1 つの実装計画を作り、1 段階ずつリリースする。後の段階の詳細計画は、前の段階が終わった時点のコードと計測結果をもとに書く（段階 3 は試行の合格率で内容が変わるため、先に細部を決めない）。

| 段階 | 計画ファイル | 設計書の節 | 始める条件 | 終わりの条件 |
|---|---|---|---|---|
| 0. 安全網と即効修正 | `2026-11-16-stage0-quick-fixes.md`（作成済み） | 8 章 段階 0 | なし | E2E・ユニット・lint がすべて通る。ドラッグ中の服の再描画 0 回、保存書き込み 0 バイト。着ている服の保存が 1 枚 300 バイト以下 |
| 1. 配信方式への切り替え | 段階 0 完了後に作成 | 7.1、7.3、7.5 の横画面固定 | 段階 0 完了。画像用の別リポジトリ（`DressUpGame-content`）を作者が作成 | iPad で取り込みなしに全アイテムが出る。移行前後の写真が一致。IndexedDB・JSZip・設定画面・縦画面のコードが無い |
| 2. 素材スタジオ | 段階 1 完了後に作成 | 7.2、10 章 1〜3 | 段階 1 完了 | 作者のサンプル（緑シルエット 2 枚）が手直しなしで登録・公開できる。色が近い画像で警告が出る |
| 3. テーマから自動生成 | 段階 2 完了後に作成 | 7.7、10 章 1 | 段階 2 完了。Claude API キーと Gemini API キーを作者が用意 | 最初に 10〜20 点の試行で合格率を記録。ドール選択 → テーマ入力 → 候補一覧 → 採用 → 公開が通る |
| 4. 描画 | 段階 1 完了後ならいつでも | 7.4 | 段階 1 完了 | PixiJS が依存から消える。JS 合計 gzip 100 KB 以下。調整中の表示と確定後の表示が一致 |

| 6. 説明書 | 最後 | 7.6 | 段階 3 完了 | 説明書が 1 つ。README が実際の動作と一致 |

## 各段階で必ず行うこと

- 設計書 2 章と同じ手順で計測し、結果をその段階の計画ファイルの末尾に追記する。
- iPad Safari での確認項目を作者に渡す（ドラッグ、調整、オフライン、バックグラウンドからの復帰）。
- `main` へのマージは作者の確認後に行う（`main` への push で GitHub Pages に自動配信されるため）。

## 作者に用意してもらうもの

- 段階 1 の前: 画像用リポジトリ `DressUpGame-content` の作成と GitHub Pages の有効化。
- 段階 3 の前: Claude API キー（Claude Console）と Gemini API キー（Google AI Studio）。どちらも PC の環境変数に置き、リポジトリには入れない。
