## 決めたこと

作者が決めたこと（計画書・設計 2〜6 章）
- 売るのは Web アプリのまま、Stripe の Checkout（カード）。期限は買った日から 6 か月。買うのはログインした保護者（保護者の確認 → パック → 最終確認で同意 → 支払い）。
- 作者が配ったチケット・ようこそのチケットは `free`（期限なし）。買った分だけ `lots`（期限つき）。

作る途中で、こちらで決めたこと
- `addMonthsJst` は、アプリ側の `src/cloud/expiry.ts` に置いた（`wallet.ts` が再公開）。`tools/cloud` はもともと `src/cloud/wire.ts` を読んでいるので、向きは変わらない。
- 払われたのに購入の記録が無いとき（支払いページを作ったあと、記録を書くのに失敗した）、知らせの `metadata`（uid・pack・tickets・expiresAt）が正しければ、記録を作り直してチケットを足す。「払われたのにチケットが無い」を避けるほうを、設計 5-3 の「足さない」より優先した。外の環境の知らせは、署名が合わない・metadata が無いので、足されない。利用者がいない（消えた）ときは、記録して 200（送り直しの繰り返しにしない）。
- ようこそのチケットは、`src/cloud/session.ts` が、利用者の世界を作ったとき（最初の `signIn` の前）に受け取って持っておき、`AppStudio` が出して消す。`signIn` は起動のときで、「つくる」を開くよりずっと前なので。
- 偽の裏側が、手で書いた `tickets` を、サーバーと同じ決まり（`ticketsWritten`）で `free` に入れる。
- ログインしていない人が「チケットを買う」を押したら、保護者の確認の前に、ログインの案内を出す（設計 5-1）。サーバーが「ログインが要る」と断ったときの案内は、保険として残した。
- 「つくる」を出さない端末に `?pay=` で戻ったときは、小さなお知らせだけ（「つくる」は開かない。チケットはアカウントに付いているので、あとで見られる）。
- Stripe のページの期限は `max(設定の 30 分, 今 + 31 分)`（Stripe は 30 分より先を求める）。
- （のち、最終レビュー後の直しで、カードだけにした。下の「最終レビュー後の直し」を見る。）Stripe の知らせは、設計の 4 つに `checkout.session.async_payment_succeeded` を足した 5 つ（遅れて済む支払いのため）。`async_payment_failed` は何もしない（購入は `open` のまま。30 分で期限切れ）。
- 知らせの送り先は、ライブラリと同じ API バージョン `2026-11-18.endive` で作る。
- `PaymentGateway.parseEvent` は非同期（返金・取り消しの知らせから、元の支払いを引くのに通信が要る）。
- 署名の失敗だけ 400、それ以外の失敗は 500（Stripe が送り直す）。足せなかったときは、ログに `【要手当て】` を出す。
- 秘密の値は、持つ関数だけが読む（`studioWork`・`studioSweep` は Stripe の鍵を、`stripeHook` は Gemini の鍵を読まない）。
- 偽の知らせの署名は、本文の HMAC-SHA256（16 進）。Stripe の `t=…,v1=…` の形は、まねない。
- ページ（`public/legal/`）: 外の読み込みの無い素の HTML。「法律の専門家の確認ではない下書き」ということは、ページには書かず、この記録と作者への報告に書く。
- E2E の保護者の確認の問いを解く表に、`一` が無く、「十一 かける …」が出ると落ちていた（9 回に 1 回）。表に足した。

## 残したこと

法律・運用（作者待ち）
- **ページの `【作者が記入】`（名前・住所・電話・メール）。決まるまで売り始めない。** ページの文は、こちらの下書きで、**法律の専門家の確認ではない**。1 回分のチケットが前払式支払手段に当たるか・6 か月で足りるか、特定商取引法の読み方（氏名まで省けるか）は、専門家に確かめてほしい。
- 値段とパック（`packs`）、ようこその枚数（`welcomeTickets`）。
- 本物の Stripe は、**試し用の鍵（`sk_test_`）でも 1 回もつないでいない**。checkout → 支払い → 知らせ → 返金の通しは、作者の試しが初めて。特に、`checkout.sessions.list({payment_intent})`、`constructEvent` に本文の Buffer を渡す所は、実機で未確認。
- iPad・スマホのホーム画面アプリから Stripe のページへ移り、戻ってこられるか（未確認）。戻れなかったときの保険は、アプリの「戻る」で戻ったときに押し直せる所まで。
- 返金は、Stripe の管理画面で手で行う。

サーバー
- 支払いページを作る前に、1 日 10 回の枠を使う（作れなかったときも 1 回ぶん数える）。1 日の区切りは UTC（朝 9 時 JST）で、ほかの上限と同じ。
- `shopAck`（「ふえました」を出した印）は、購入の状態を見ない（`open` のものに付けると、あとで `paid` になったとき知らせが出ない。アプリはそうしない）。
- `markWelcome` が、すでに開いた利用者を読み直す（無駄な 1 回の読み）。
- `async_payment_failed` は何もしない。
- メモリの置き場と Firestore の置き場で、負の数・0 の扱いが違う（Firestore は `Math.abs`）。呼ぶ側が正の数を渡す前提。
- 引き継ぎ（`moveTickets`）で、移す元の期限切れの lot の記録が、元の台帳に残らない。
- `wallet.ts`: 数が NaN のとき・費用が 0 や小数のときの守りが無い（呼ぶ側が正の整数を渡す前提）。引いた lot が使い切られたあとの返金は、`free` に入る（期限を失う）。
- `WireUser` の `free`・`lots` は必須の型だが、古いサーバーは返さない（アプリ側で `?? ` で受けている）。型を `Partial` にすると正確。
- Stripe のクライアントは、鍵の組ごとに 1 つ持つ。

アプリ・偽の裏側
- 買う画面・ログインの案内・お知らせの重なりに、`role="dialog"`・フォーカスの扱い・背景のスクロール止めが無い。
- 偽の裏側: 払い戻しの分が `free`（期限なし）に入る。1 日 10 回の上限・同意の記録は無い。`shop()` の中で `credit` を呼ぶ（読みが書きを起こす）。`fakeOptions()` が `shop`・`fakeLots` の中身を確かめない。`payResult` の既定値のテストが無い。
- 偽の「遅い」の E2E は、本物の時間で 45 秒ほどかかる（重いと時間切れになったことがある）。
- 「つくる」のチケット欄は、`user.lots[0]` が期限のいちばん近い lot という前提（偽は並べている。本物の返し方も同じか）。
- 期限の表示は、日本時間の日付の境目で、サーバーの計算と 1 日ずれることがある。
- 戻る（bfcache）で戻ったときの「ひらいています…」は直した（押し直せる）。

## 最終レビュー後の直し（fix wave）

- 鍵が本物の形（`sk_`・`whsec_` で始まる）でなければ、鍵が無いのと同じ扱い（`stripeKeysUsable`。単体テストあり）。仮の値 `pending` で載せられ、買うは `pay:closed`、`stripeHook` は何もせず 503。`docs/firebase-setup.md` の 2-12・2-14 に書いた。
- 管理者にも、「管理者（制限なし）・🎫 のこり N 枚」と、買った分の期限の行を出す（試しに買った結果が見えるように）。2-14 の 6・8 の文を、見える画面に合わせた。
- 支払い方法はカードだけ（`payment_method_types: ['card']`。Apple Pay・Google Pay はカードの一種）。登録するイベントは 4 つに戻した（`async_payment_succeeded` は書かない）。コードの `async_payment_succeeded` の受け口は、害が無いので残した。公開ページ・設定の文書の言い方を合わせた。
- 公開ページ: プライバシーの「名前・メールは保存しない」を直した（Firebase Authentication が持つ。目的はログインだけ）。利用規約の保護者の確認を「かんたんな確認」に和らげた。「もどる」は、アプリへのふつうのリンクにした。特商法の動作環境は「チケットを買うには」ログインが要る、に直した。
- チケットの守り: 新しい形の利用者で `tickets` が有限の数でないときは、手で書き換えた差を見ない（0 と読んで買った分まで引かない）。`tools/cloud/wallet.ts`・`src/cloud/fakeBackend.ts` の両方。テストあり。
- 文書: firebase-setup の読みにくい文、HANDOFF 0-A の順番（7 の次に 8）。
