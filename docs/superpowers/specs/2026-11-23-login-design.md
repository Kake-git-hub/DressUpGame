# 段階 ③ ログイン（Google のアカウントと結び付ける）: 設計書

2026-11-23。作業ブランチ `claude/quirky-cori-3yr6ov`。前の段階: ①（v0.35.0）・②（v0.36.0）、Issue の直し（v0.36.1）。

## 1. 依頼と、なぜ作るか

- 作者の依頼（2026-11-23 の 6 段階の計画の ③）: Google のアカウントと結び付けて、**複数の端末で同じアカウントを使えるようにする**（きょうだいで共有。iPad とスマホで、同じチケットと同じ服）。
- いまは、端末ごとに別の「名前の無い利用者」（Firebase の匿名のログイン）。チケットと作った服は、その端末にしか出ない。アプリのデータを消す・端末を替えると、取り戻せない。
- あとの段階（⑥ 支払い）で、買ったチケットを無くさないための土台にもなる。

## 2. 目標・やらないこと・起きてはいけないこと

**目標**

1. 「つくる」の中（保護者の確認のあと）から、Google のアカウントでログインできる。いまの端末のチケットと服は、**そのまま**そのアカウントのものになる。
2. 2 台めの端末で同じ Google に入ると、同じチケットと服が出る。その端末にログイン前からあったチケットと服は、**アカウントに合わせる**（足す。無くならない）。
3. iPad・スマホのホーム画面アプリで、Google のログインの画面が開けて、戻って来られる方法を、**実機で確かめて決める**。

**やらないこと（この段階では）**

- Apple のログイン（Apple Developer の登録が済んでから。作者の決定）。
- ログインを必須にすること（ログインしなくても、いままでどおり全部使える）。
- 「つくる」を教えていない端末にログインを出すこと（販売を始めるまでは、教えた端末にだけ。① の決定）。
- アカウントを消す画面、2 つの Google アカウントをまとめること。

**起きてはいけないこと**

- チケットや服が無くなる（ログイン・ログアウト・失敗のどの道でも）。
- ログインに失敗したせいで、「つくる」やクローゼットが使えなくなる。
- 子どもが、間違ってログアウトする・ほかのアカウントに入る（→ 7.4。「つくる」の保護者の確認は、いまは切ってある = `src/App.tsx` の `ASK_ADULT = false`、v0.32.0 の作者の指示。アカウントの欄の守りは、別に決める）。
- きろく（`log`）や GitHub の報告に、メールアドレスや、ログインの鍵（トークン）が入る（このリポジトリの Issue は、だれでも読める）。

## 3. いまの作り（調べたこと）

- 利用者は、Firebase の匿名のログインの番号（`uid`）。アプリは `src/cloud/firebaseTransport.ts` で、匿名でログインしてから、サーバーの関数 `studio` を呼ぶ。サーバーは、チケット・仕事・服を `users/{uid}/…` に持つ（`functions/src/firestoreStore.ts`）。新しい利用者のチケットは 0 枚。
- 管理者は、Firestore の `system/config` の `adminCodes`（利用者コードの一覧）。利用者コードは `uid` に付く。
- **匿名の利用者に Google を結び付けても、`uid` は変わらない**（Firebase の仕組み）。だから、1 台めの端末は、**サーバーを変えずに**ログインできる（チケット・服・利用者コード・管理者の印は、そのまま）。
- 2 台めの端末は、別の `uid`（匿名）を持っている。同じ Google に入ると、Firebase は「この Google は、もう使われている」と断る（`auth/credential-already-in-use`）。そこで、1 台めの `uid` に入り直す。2 台めの匿名の `uid` のチケットと服は、**サーバーで移さないと、置き去りになる**（→ サーバーの変更と、作者の載せ直しが要る）。
- アプリは GitHub Pages（`kake-git-hub.github.io`）にあり、Firebase のログインの部品の置き場（`dressup-game-89f6e.firebaseapp.com`）とは別の場所。このため、Firebase の「画面を移る」方式（`linkWithRedirect`）は、いまのブラウザでは動かない（Firebase の公式の説明。GitHub Pages では、公式の回避策のうち「小さい窓」と「自分で Google とやり取りする」だけが使える）。
- 端末の控え（`library`）には、「前の利用者だったころの服」（`owner` が、いまの利用者コードと違う・無い）が残っていることがある。サーバーに無くても、端末で着られるように、わざと残している（`src/cloud/sync.ts`）。**ログインの作りで、これを消してはいけない。**
- アプリは、新しい版を見つけると、自動で読み込み直す（`registerSW` の `autoUpdate`）。Google から戻った直後に、これが起きることがある（→ 7.2 の 4）。
- **作者の Firebase では、Google のログインが、まだ有効になっていない**（2026-11-23 に、こちらから確かめた。`OPERATION_NOT_ALLOWED`）。作者の作業が要る（9 章）。

## 5. 作り方の案（Google のログイン画面の出し方）

iPad・iPhone のホーム画面アプリでどうなるかは、**どの方法も、資料では確かめられなかった**（古い報告は「小さい窓は、結果がアプリに戻らない」。新しい版の iOS での報告は見つからない）。実機で試すしかない。

| 案 | 中身 | 良い所 | 弱い所 |
|---|---|---|---|
| 1. 小さい窓（Firebase の `linkWithPopup`） | ボタンを押すと、Google の画面が別の窓で開く。終わると窓が閉じて、アプリに結果が届く | 作りが小さい。作者の設定が少ない（Google を有効に・ドメインを 1 つ足す）。PC・スマホのブラウザ・Android のホーム画面アプリでは、まず動く | iPad・iPhone のホーム画面アプリでは、窓がアプリの外で開いて、結果が戻らないという報告が多い |
| 2. 画面を移る（自分で Google とやり取りする） | アプリの画面そのものが Google の画面に替わる。終わると、アプリの URL に戻って来る（戻って来た URL に付いている「ログインの証明」を、Firebase に渡す） | 窓を使わない。ブラウザの「よその場所の保存を断る」設定に左右されない。ふつうのブラウザでは、いちばん確実 | 作者の設定が 1 つ増える（Google Cloud の画面で、戻り先の URL を登録）。iPad・iPhone のホーム画面アプリで、戻って来たときにアプリに戻るか、Safari に取り残されるかは、分からない |
| 3. Google の公式のボタン（Google Identity Services） | Google が用意したボタンと小さい窓 | 見た目が公式 | 小さい窓なので、案 1 と同じ弱点。iPhone では「画面を移る」形が要り、それにはサーバーの受け口が要る。案 1・2 より得る所が無い |
| 4. Firebase の「画面を移る」（`linkWithRedirect`） | — | — | GitHub Pages では動かない（3 章）。**使わない** |
| 5. 別の端末で認める（アプリに出した QR や短いコードを、Safari などで開いてログインし、アプリに引き継ぐ） | アプリの中で Google の画面を開かない | どの端末でも動くはず | 作りが大きい（サーバーの受け口・鍵を出す権限の設定）。使う人の手間も多い |

**選んだもの**: 試し版には、**案 1 と案 2 の両方**を入れて、作者に両方を試してもらう（1 回のやり取りで、どちらが動くか分かる）。結果を見て、端末ごとに使う方法を 1 つに決める（③-b）。両方とも iPad で動かなければ、案 5 を設計し直す。

## 7. ③-a（試し版）の設計

### 7.1 画面（「つくる」の中。大人向けなので、漢字かな交じり）

「つくる」のいちばん下、利用者コードの行の上に「アカウント」の欄を置く。

```
ログインしていないとき:
┌ アカウント ─────────────────────────────┐
│ Google のアカウントでログインすると、ほかの端末でも、   │
│ 同じチケットと服を使えます。                            │
│ [ Google でログイン（方法 1: 小さい窓） ]               │
│ [ Google でログイン（方法 2: 画面を移る） ]             │
│ ためしの版です。どちらの方法で、うまくいったか・        │
│ いかなかったかを、きろく（log）から報告してください。   │
└─────────────────────────────────────┘

ログインしているとき:
┌ アカウント ─────────────────────────────┐
│ ログイン中: taro@example.com               [ログアウト] │
└─────────────────────────────────────┘
```

- メールアドレスは、隠さずに、そのまま出す（本人の端末の、大人向けの画面）。きろくには出さない（7.3）。
- **ボタンは、準備（Firebase の読み込み・いまの利用者の確かめ・「この端末が空か」の確かめ）が済むまで、押せない。** 方法 1 の小さい窓は、押した、その瞬間に開かないと、ブラウザ（とくに iPad・iPhone）が止める。押してから何かを待つと、「方法 1 は動かない」という、まちがった結果になる。
- 押してから結果が出るまで、ボタンは押せなくして「ログインしています…」。
- 結果は、欄の中に 1 行で出す（7.4 の文）。
- 方法 2 で戻って来たときは、アプリが読み込み直されて、ホームになる。**ホームの上に、結果の知らせ**（「Google のアカウントでログインしました」／できなかった理由。「OK」で閉じる）を出す。
- 偽物の裏側（`?studio=fake`。確認用）でも、同じ画面が、にせものの動きで出る（E2E と、作者の見た目の確認のため）。

### 7.2 流れ

**先に決めること（押す前）**: 「この端末が空か」で、Google にしてもらうことが変わる。

- **空でない端末**（ふつうの 1 台め）: いまの利用者に、Google を**結び付ける**（`uid` は同じ。チケットも服も、そのまま）。
- **空の端末**（ログアウトしたあと・まっさらな 2 台め）: その Google のアカウントに**入る**（初めての Google なら、新しいアカウントができる）。空の「名前の無い利用者」は、置いていく（何も持っていないので、無くなるものは無い）。

「空」とは: サーバーに聞いて、チケット 0 枚・自分の服 0 点・見ていない仕事（作りかけ + 結果をまだ見ていない）0 件で、**管理者でない**こと（管理者の印と利用者コードは `uid` に付いている。管理者の端末が別のアカウントに入ると、印が外れるので、いつも「空でない」扱い）。聞けなければ、空でない扱い。端末の控えに残っている「前の利用者の服」は、数えない（消さないので、関係ない）。

*空の端末で「入る」と、利用者コードが替わる。作者が、その端末の古い利用者コードにチケットを配ろうとしていた所なら、届け先が変わる（まれ。試し版では、そのまま）。*

*Google の証明は、1 回しか使えない見込み（合い言葉 `nonce` 入りの証明を 2 回出すと、Firebase が断る）。だから、「結び付けてみて、だめなら入り直す」ではなく、押す前に、どちらかに決める。*

**方法 1（小さい窓）**: ボタンを押した、その場で（何も待たずに）、空でなければ `linkWithPopup(いまの利用者, Google)`、空なら `signInWithPopup(Google)`。

**方法 2（画面を移る）**:

1. ボタンを押す → 使い捨ての合い言葉を 2 つ作って（`state`・`nonce` のもと。乱数）、「結び付ける／入る」のどちらか・時刻と一緒に、端末に覚える（`localStorage`。ホーム画面アプリで、Google の画面から戻ったときに消えていないように。10 分で無効）。
2. Google の画面へ移る: `https://accounts.google.com/o/oauth2/v2/auth` に、`client_id`（Firebase が作ったウェブ用のもの）・`redirect_uri`（アプリの URL。`https://kake-git-hub.github.io/DressUpGame/`）・`response_type=id_token`・`scope=openid email`・`nonce`（もとの乱数の SHA-256）・`state`・`prompt=select_account`。
3. Google が、アプリの URL に戻す（URL の `#` のあとに `state` と `id_token`、または `error`）。
4. アプリは、起動のいちばん最初（自動の更新の仕組みを動かす前）に、URL の `#` を見る。ログインの戻りなら、**その場で URL から消して**（`history.replaceState`。きろく・共有・履歴に残さない）、中身を、そのタブだけの一時の置き場（`sessionStorage`）に移す。**使い終わるまで、そこに置く**（直後に自動の更新で読み込み直されても、無くならないように。使ったら・10 分たったら、消す）。
5. `state` が覚えたものと同じで、10 分以内で、`id_token` の中の `nonce` が、もとの乱数の SHA-256 と同じなら、受け取る。違えば、捨てて「もう一度」と出す。
6. Firebase を読み込み、証明を渡す（`new OAuthProvider('google.com').credential({ idToken, rawNonce: もとの乱数 })`。Firebase の決まり: `nonce` 入りの証明には、もとの乱数を付ける）。覚えておいた「結び付ける／入る」のとおりに、`linkWithCredential` か `signInWithCredential`。ただし、「入る」と覚えていても、戻って来たときに端末が空でなくなっていたら（作りかけが届いた、など）、「結び付ける」にする。

`client_id` は `src/cloud/firebaseConfig.ts` に書く（公開してよい値）。**作者が Google を有効にするまで、値が分からない**ので、空のときは、アプリが Firebase に聞いて調べる（Firebase の公開の受け口 `accounts:createAuthUri` の返事に入っている。欄を出したときに調べておく）。作者が有効にしたら、こちらで調べて書き込む（次の版から、聞かずに済む）。

**結果**（方法 1・2 で共通。`src/cloud/account.ts`）:

| 起きたこと | すること | 結果 |
|---|---|---|
| 結び付けられた | 何も移さない（`uid` は同じ） | 「ログインしました」。欄を「ログイン中」に |
| 空の端末で、入れた | 読み込み直す（つなぎ役が、そのアカウントのチケットと服を取って来る） | 「ログインしました」。そのアカウントのチケットと服が出る |
| 結び付けようとしたら、この Google は、もう使われていた（`credential-already-in-use`） | 何もしない | 「この Google のアカウントは、ほかの端末で使われています。この端末のチケットと服を合わせるのは、次の版でできるようになります」 |
| やめた（窓を閉じた・Google の画面で「キャンセル」） | 何もしない | 「ログインを やめました」 |
| 作者の設定がまだ（`operation-not-allowed`・`unauthorized-domain`） | 何もしない | 「Google のログインの準備が、まだできていません（作者の設定待ちです）」 |
| 窓が開けなかった（`popup-blocked`・`operation-not-supported-in-this-environment`） | 何もしない | 「小さい窓を開けませんでした。方法 2 を試してください」 |
| そのほか | 何もしない | 「ログインできませんでした。少し待ってから、もう一度ためしてください」 |

**ログアウト**: 「ログアウト」→ 確かめる（「ログアウトすると、この端末では、チケットと作った服が見えなくなります。アカウントには残っていて、同じ Google でログインすると戻ります。」［ログアウトする］［やめる］）→ `signOut` → 端末の控えから、**そのアカウントの服だけ**（`owner` が、いまの利用者コードの服。サーバーに残っている）を外し、つなぎ役の覚え（NEW の印・届いた仕事）を消して、読み込み直す。「前の利用者の服」（3 章）は、触らない。次に「つくる」やクローゼットを開くと、新しい「名前の無い利用者」（空）になる。作りかけの仕事があっても、止まらない（サーバーが進めて、アカウントに届く）。

ログアウトしてから、同じ Google に方法 1・2 のどちらかで入り直せる（端末が空なので、「入る」）。**作者は、これで、1 台の端末で両方の方法を試せる。**

### 7.3 きろく（`log`）に残す行

メールアドレス・証明（トークン）・`state`・`nonce` は、**残さない**。

- `login start popup` / `login start redirect`
- `login back ok` / `login back none`（覚えが無い）/ `login back mismatch` / `login back expired` / `login back error=<Google の理由の語>`
- `login result linked` / `switched` / `taken` / `cancelled` / `not-ready` / `no-popup` / `failed code=<Firebase の理由の語>`
- `login out`

### 7.4 起きてはいけないことへの守り

- **無くならない**: 試し版で `uid` が替わるのは、「端末が空」と確かめたときと、ログアウト（確かめのあと）だけ。端末の控えから外すのは、サーバーに残っている服だけ。ログアウトで見えなくなるのは、ログインしているアカウントのもの（アカウントに残る）。**ログインしていない端末には、ログアウトのボタンが無い**（名前の無い利用者を捨てる道は、作らない）。
- **「つくる」が止まらない**: ログインの失敗は、欄の中の 1 行だけ。いまの利用者（匿名）は、そのまま。
- **子ども**: 保護者の確認は、出さない（作者の決定、2026-11-23。聞き直した答え: 「確かめの文だけ」）。ログアウトは、確かめの文（7.2）のあとにだけ起きる。間違ってログアウトしても、同じ Google で入り直せば戻る（無くならない）。
- **ほかの人の服が残らない**: ログアウトのとき、そのアカウントの服を端末の控えから外す。
- **きろくに漏れない**: Firebase の失敗の中身には、メールアドレスが入っていることがある（`customData.email`）。きろくには、理由の語（`auth/…`）だけを書く。警告・エラーとして書き出すときも、中身をまるごと渡さない。テストで確かめる。
- **戻りの URL**: `state` と `nonce` で、よそから差し込まれた証明を受け取らない。証明そのものの確かめ（本物の Google のものか・このアプリ宛てか）は、Firebase がサーバーで行う。

### 7.5 サーバーが古い・設定がまだ、のとき

- ③-a は、サーバーを変えないので、いまのサーバー（v0.35.0 の版）で動く。
- 作者の設定（9 章）が済む前に公開しても、困らない: 「Google のログインの準備が、まだできていません」と出るだけ。方法 2 は、`client_id` を調べられなければ、同じ文を出して、Google の画面へは移らない。

### 7.6 確かめ方

- ユニット（先に書く）: 方法 2 の純粋な部分（Google へ移る URL の組み立て・戻りの URL の読み取り・`state`／期限／`nonce` の確かめ・URL から消す・読み込み直しをはさんでも残る）、「空か」の決め方（管理者・聞けないとき）、結果の表の全部の行（Firebase の部品は、差し替えて）、ログアウトで外す服（いまの利用者の服だけ）、アカウントの欄の表示（ログイン前・中・結果の文・ログアウトの確かめ）、きろくにメールアドレスと証明が入らないこと。
- E2E（偽物の裏側）: 方法 1 でログイン → 欄が「ログイン中」→ 読み込み直しても同じ → ログアウト → クローゼットが空 → 方法 2 で入り直す（にせものの「画面を移る」で、起動時の戻りの処理と、ホームの知らせを通す）→ 服が戻る。空でない端末で「もう使われている」→ 何も変わらず、文が出る。
- こちらでは確かめられないこと: 本物の Google の画面（こちらには、試せる Google のアカウントが無い）、Firebase が方法 2 の証明（`nonce` 入り）を受け取るか、iPad・スマホのホーム画面アプリでの動き。**作者に試してもらう**（9 章の 2）。

## 8. ③-b の骨組み（細かい設計は、試し版の結果のあと）

- 2 台めの端末（空でない）で「もう使われている」となったら、**先にサーバーで、この端末の匿名の利用者のチケットと服を、そのアカウントへ移す。移し終えてから、アカウントに入り直す**（この順なら、入り直しに失敗しても、チケットと服はアカウントに入っていて、無くならない）。
- サーバーの新しい受け口（関数 `studio` の中）: 呼んだ人（匿名）が、Google の証明を一緒に渡す。サーバーは、証明を確かめて、そのアカウントの `uid` を調べ、チケットを足し（台帳に残す）、服を移す。何度呼ばれても、2 重に足さない。作りかけの仕事の服は、できたときに、アカウントのほうへ入るようにする。
- サーバーが古いとき（載せ直しの前）: 「サーバーが古い版です」と出して、何も変えない（① と同じ守り）。
- ログインのボタンは 1 つにする（端末ごとに、試し版で動いた方法を使う。もう片方は、「うまくいかないとき」として残すかを、結果を見て決める）。

- 偽物の裏側での、「もう使われている」などの出し方（`dressup_fake_options` に足す）。

- 設計から変えた所・足した所（点検と、全体レビューで出た点）:
  - 「結び付けてみて、だめなら入り直す」は、やめた。**押す前に「この端末が空か」で、結び付ける／入るを決める**（Google の証明は 1 回しか使えない見込み）。欄を出している間も、20 秒ごと・画面に戻ったとき・チケットや仕事が変わったときに、聞き直す。
  - 管理者の端末は、いつも「結び付ける」。
  - ログアウトは、利用者コードが分からないとき（つながっていない）は、しない（アカウントの服が、端末に残らないように）。

  - Google から戻った起動では、戻りを仕上げてから、つなぎ役を出す（古い利用者のままの合わせと、競り合わない）。
  - 方法 2 で Google の画面から「戻る」で帰って来たら、「ログインを やめました」と出して、もう一度押せる。
  - 「つくる」を教えていない端末に戻りが来たら、証明を捨てる。
