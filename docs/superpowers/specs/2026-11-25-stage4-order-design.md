# 段階 ④ 並び順: PC スタジオの「ならべかえ」画面（設計）

2026-11-25。作者と決めたこと（カードで）をまとめる。写真: `2026-11-25-stage4-order/`（`0-now.png` = いま、`A-small.png` = 案A、`B-sort-view.png` = 案B）。

## 1. なぜ

- 作者の言葉: 「PC でもいいが、カテゴリごとの並べ替えもしたい。また数値管理がめんどくさいので、スタジオの並び順で管理したい。PC スタジオのサムネが大きすぎるので小さく。」
- いま: カテゴリの順番は、数字（「並び順」の欄）で入れる。同じ数字のカテゴリがある（てぶくろ・ソックスが 3）。服の順番は、絵のドラッグか ◀ ▶ で変えられるが、絵が 120px で、絵の下に操作が並ぶので、おんなのこ（147 点）で縦に約 12,000px。並べ替えるのに長くスクロールする。
- 0-1 の表の ④ は「管理者のアカウントだけが、アプリで変える」だったが、作者は **PC スタジオでよい**とした（PC スタジオは、作者の PC にしか無い = 管理者だけ）。**アプリ・サーバーは変えない。**

## 2. 目標・しないこと

- 目標: PC スタジオで、カテゴリ・服・セットの順番を、**つかんで動かすだけ**で決める。並べた順番が、そのままゲームのメニューの順番になる（公開すれば）。数字は入れない。1 つのドールの全部が、画面 2 枚ほどで見渡せる。
- しないこと: アプリの中（iPad など）での並べ替え。利用者ごとの並び。自分で作った服（クローゼット）の並び（いまの「並び」のまま）。カテゴリをまたいで服を動かすこと（カテゴリを変えるのは、いままでどおり「くわしく」のプルダウン）。
- 失敗とみなすこと: スタジオで並べた順番と、ゲームのメニューの順番が食い違う。公開されている素材を取り込んだら、並べた順番が戻る。

## 3. 案（作者が B を選んだ）

| 案 | 中身 | 得失 |
|---|---|---|
| A | いまの一覧のまま、絵を 120 → 76px | 画面は 1 つで済む。絵の下の操作が残るので、縦は約 9,300px（あまり縮まない） |
| **B（選んだ）** | 「一覧」の上に「くわしく｜ならべかえ」の切り替え。ならべかえは、絵（64px）だけを詰めて並べる | 147 点で約 1,600px（画面 2 枚）。並べ替えに集中できる。名前・消すなどは「くわしく」に分かれる |

## 4. 作り（B）

**画面**（`src/studio/Panels.tsx` の `Library`。写真 `B-sort-view.png` の形）

- 「一覧」のいちばん上に、切り替え「くわしく（いまの一覧）｜ならべかえ」。どちらを開いていたかは、PC に覚える（`localStorage`。読めなくても「くわしく」で開く）。
- **カテゴリの順番**: 上の帯に、カテゴリの名前と点数のチップを、ゲームのメニューの順に横に並べる。チップをつかんで左右に動かすと、順番が変わる。
- **セット**: セットの段（4 つまでのパーツの絵を並べた 64px の絵。名前は、絵に重ねるか、マウスを置くと出す）。つかんで動かすと、セットの順番が変わる。
- **服**: カテゴリごとの段に、64px の絵を詰めて並べる（左上に順番の数字）。つかんで、同じカテゴリの中で動かす。落とす先には、縦の線を出す（写真の紫の線）。
- 服の絵を押す（動かさずに離す）と、「くわしく」に切り替わり、その服の所までスクロールする。
- 「くわしく」の側: カテゴリの「並び順」の数字の欄は外す（順番は、ならべかえで決める）。「重ね順」（重なりの順番）の数字は残す。服の ◀ ▶ とドラッグ、セットの ▲ ▼ は残す（そのままで困らない）。

**保存**

- カテゴリ: 動かしたら、そのドールの全部のカテゴリの `menuOrder` を、並びの順に 0, 1, 2… と振り直す（同じ数字が無くなる）。いまある口 `POST /api/categories/order`（`reorderCategories`。`layer` は、いまの値をそのまま送る）を使う。
- 服: いまの `POST /api/items/order`（`reorderItems`。素材の一覧の服の並び = メニューの順）。
- セット: いまの `POST /api/sets/order`（`reorderSets`）。
- 新しいカテゴリを作ったときは、いままでどおり最後（いちばん大きい数 + 1）。

**ゲームの側**（変えない）: メニューはカテゴリを `menuOrder` の順、服を素材の一覧の順に並べている（`src/content/loadContent.ts`・`src/components/DressUpMenu.tsx`）。うしろがみ（`menuOrder + 0.5`）も、そのまま。

## 5. 確かめること

- ユニット: 振り直しの計算（動かした先・同じ数字があるときの並び = いまの見え方の順を保つ）。
- E2E（スタジオ）: ならべかえで、カテゴリ・服・セットを動かす → 素材の一覧が変わる → 読み込み直しても、その順。服の絵を押すと、くわしくのその服へ。
- 取り込み: 公開されている素材を取り込んでも、PC で並べたカテゴリの順番が残るか（服の順番は v0.28.0 で残るようにした。カテゴリの `menuOrder` も同じ扱いかを、計画のときに `tools/content/` で確かめる。残らなければ直す）。
- 写真: ならべかえ画面を、作者に見せる。

## 6. 作る人に任せること

- ドラッグのやり方（HTML のドラッグ＆ドロップで十分。PC だけ）、落とす先の線の見せ方、セットの名前の見せ方。
- 「くわしく」へ移ったときの、服の目立たせ方。
- 版数（ゲームの動きは変わらないが、スタジオは同じリポジトリなので v0.39.0 として README に書く）。

## 7. 作者に確かめてもらうこと

- PC で `npm run studio` → 「一覧」→「ならべかえ」で並べ替え → 「公開」→ ゲームのメニューがその順になるか。
