# v0.45.0 の設計: クローゼットで、自分の服の「はじめの位置」を決める（2026-11-26）

計画: `../plans/2026-11-26-next-features-plan.md` の 4。**サーバーを変える（作者の PC での載せ直しが要る）**。画像生成 0 枚。

## 1. 作者が決めたこと（2026-11-26、カードで）

- 決める所は **クローゼットだけ**（着せ替えの調整画面には、ボタンを置かない）。
- 覚えるのは **位置・大きさ・向き**（重なり・色は覚えない。色は、いままでどおりクローゼットの「いろ」）。
- 交換で渡した服は、はじめの位置も **一緒に渡す**（もらった人は、あとから直せる）。
- 決める画面は、**着せ替えと同じ調整画面**（v0.44.0 のもの。スマホ縦は虫めがねつき）。クローゼットの服の画面の「いちを きめる」で開き、✓ で覚える。

## 2. 作り

### 2-1. 持ち物

- `ItemFit = { x, y, scale, rotation }`。x・y は「ドールの絵の px」（`src/engine/units.ts` と同じ単位。画面の大きさ・向きが変わっても、ドールに対して同じ所）。scale 0.3〜2.5、rotation -180〜180。
- サーバーの服（`ItemDoc`）に `fit?`。通信の服（`WireItem`）・端末の控え（`MyItem`）にも `fit?`。無ければ、もとの位置。
- ゲームの服（`ClothingItemData`）に `defaultFit?`。自分の服を素材に重ねるとき（`mergeMyItems`）、前髪・うしろがみの両方に付ける。

### 2-2. サーバー（`SERVER_API` 7、`FIT_API` 7）

- `updateItem` が `fit`（ItemFit、または null = 消す）を受け取る。数でない値は断る。範囲の外は、範囲に収める。x・y は ±1024 まで。
- 交換は、服の文書をそのまま相手へ移すので、`fit` も一緒に移る（コードは変えない。テストで確かめる）。
- 載せ直す前のサーバー（`api` < 7）: クローゼットの「いちを きめる」を押せなくし、「サーバーが ふるい はんです」と出す。ほかは、いままでどおり。

### 2-3. 着せ替え

- `defaultFit` のある服を着せたとき（タップ・ドラッグ・セット・届いた服の「きてみる」）、位置・大きさ・向きを `defaultFit` から始める（`useDressUp` の `equipItem`）。
- 調整画面の「リセット」は、`defaultFit` に戻す（色が `defaultHue` に戻るのと同じ）。
- 着ている服の位置は、着せたときに写すだけ（クローゼットで変えても、いま着ている服は動かない。着せ直すと新しい位置）。

### 2-4. クローゼット

- 服の画面（`ClosetItem`）に「いちを きめる」（`closet-fit`）。つながっていない・古いサーバー・交換の話が進んでいる服では押せない（理由を出す）。決めてあるときは「いちを もとに もどす」（`closet-fit-reset`）も出す。
- 押すと、全画面の調整画面（`src/components/FitEditor.tsx`）: ドールがその服だけを着た画面で、v0.44.0 の調整画面を開く。色の帯・重なりの一覧・× は出さない。上に「はじめの いち」と「やめる」。✓ で、サーバーへ送り、通ったら端末の控えを変え、メニューに重ね直す。失敗したら、理由を出して、画面は閉じない。

## 3. テスト

- サーバー: fit を覚える・範囲に収める・おかしな値を断る・null で消す・交換で移る（`studioCore.test.ts`・`api.test.ts`）。
- 端末: 控えに fit が入る・`mergeMyItems` が `defaultFit` を付ける（髪は 2 枚とも）・着せると fit から始まる・リセットで fit に戻る。
- E2E（偽の裏側）: クローゼットで位置を決める → 着せ替えで着ると、その位置。古いサーバーでは押せない。スマホ縦でも開ける（虫めがね）。
