# 作りやすい新ドールと、部位の差し替え式生成: 設計書

- 作成日: 2026-11-19
- 状態: **完了。新ドール「アニメ　その２」と 25 点を公開済み**（10・11 章）
- 関連: `2026-11-15-lightweight-rework-design.md`（全体の設計）、`../plans/2026-11-16-studio.md`（スタジオの計画と結果）

## 1. なぜ作るか

最近スタジオで生成した「くつ」と「ヘアスタイル」の出来が悪い。実物をドール「アニメ」に着せて拡大し、原因を確かめた。

| 症状 | 原因 |
|---|---|
| 靴の中にドールの足の甲・指・黒い輪郭線が見える。左右の靴が重なる | ドールの足が「正面向きのつま先立ち」で左右がくっついている。靴はその上に重ねるだけなので、形が合わない所がすべて見える |
| 前髪のふちに緑色が残る。頭の輪郭と髪の境目ががたつく | 頭が 1024px の画像の中で幅 107px しかない。細部を描く画素が足りない |
| 服や靴が少しずれるだけで、輪郭線がはみ出して見える | ドールの輪郭線が太い（黒、数 px） |

どれも、指示文や切り抜きの手直しでは根本的に直らない（v0.17.0〜0.17.1 で手直しを重ねたが残った）。ドールの姿勢と、頭・手足の作り方そのものを変える。

作者の決定（2026-11-19）:

- **新しいドールを 3 体目として作る**。「アニメ」「リアル」と既存の服 102 点はそのまま残す。
- 靴は「ドールを部位に分けて、部位ごと入れ替える」方式にする。**顔と手も同じ差し替え式でよい**。
- 生成しやすい姿勢・大きさを一から見直す。

## 2. 試した結果（2026-11-19、本物の画像生成で 4 枚）

設計を決める前に、使い捨てのスクリプトで試した。

1. 「アニメ」を絵柄の見本にして、姿勢を指定した新しいドールを 1 枚生成（2K）。→ 頭が大きめ、細い輪郭線、足は地面にべったりで外向き、腕は体から離れた姿になった。
2. そのドールの**本物のすねから下を拡大した図**に「靴をはかせて」と頼んだ（パンプス、ファー付きブーツ。各 1 枚、1K）。→ 脚は動かず、足は靴の中に自然に収まった。
3. そのドールの**上半身を拡大したシルエット**に髪を描かせた（1 枚、1K）。→ ふちに色残りの無い、細部まで描けた髪になった。

雑な合成（調整なし）でこの出来になった: `2026-11-19-spike-new-doll.jpg`。4 枚とも 1 回目の生成で、やり直しなし。

分かったこと:

- 拡大図に描かせると、同じ 1K の画像でも部位あたりの画素が 2〜3.4 倍になり、細部の問題がほぼ消える。
- 本物の脚を見せて靴を描かせると、AI が足と靴の関係を正しく描く。足首から下を「靴の絵ごと差し替える」と、ドールの足がはみ出す問題そのものが無くなる。
- 試作のドールは、脚の間がまだ狭い。ドールは数枚作って選ぶ必要がある。

## 3. 目標と、やらないこと

**目標**

- 新ドールで、靴・髪・手袋・顔を、手直しなしで使える出来で生成できる。目安: 靴 5 点・髪 5 点を生成して、それぞれ 4 点以上が手直しなしで使える（見て判断する）。
- 新ドールがゲームで選べて、新しく作った服を着せられる。
- 新しい作り方は、ドールの部位の位置（型紙）だけに依存させ、今後ドールを増やしても同じ手順で作れる。

**やらないこと**

- 既存の 2 体と、その服 102 点の作り直し・変換。
- スタジオの画面に「ドールを AI で作る」機能を足すこと（今回はスクリプトで作り、手順と指示文をリポジトリに残す）。
- トップス・ボトムス・ドレスなどの服の作り方の変更（いまの全身シルエット方式のまま。新ドールの細い線と開いた姿勢の恩恵だけ受ける）。
- 配信画像の解像度の変更（1024px のキャンバスのまま）。
- サーバーへの設置、有料化、描画の Canvas 2D 置き換え（ロードマップの別の段階）。

**これが起きたら失敗**

- 既存のドールや服の見た目・ID・保存済みの服装が変わる。
- 靴をはくと、足首で肌の色や線がずれて、継ぎ目が見える。
- 生成の枚数（費用）が、1 品目あたり今より増える。

## 4. 考えた進め方

| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| A. いまのドールのまま、指示文と切り抜きを直す | 靴の内側を埋める、色残りを消す、など | 既存の服がそのまま使える | v0.17.x でやって、残った。原因（姿勢と大きさ）に届かない |
| B. 全品目を 2K・4K で生成する | 画像を大きくして細部を稼ぐ | 仕組みを変えずに済む | 費用が上がる。靴と足の形が合わない問題は残る |
| **C. 新ドール＋拡大図で生成＋部位の差し替え（採用）** | 姿勢を作り直し、頭・手・足は拡大図に描かせ、手足は部位ごと入れ替える | 2 章の試行で、原因が 3 つとも消えた。費用は 1 品目 1 枚（1K）のまま | 新ドールの服は一から作る。作り方がカテゴリの種類ごとに分かれる |

作者は C の方向（新ドール、部位の入れ替え）を選んだ。細部は以下のとおり、こちらで決めた。

## 5. 設計

### 5.1 新しいドール

名前は「アニメ2」（仮。作者が決める）。絵柄は「アニメ」と同じ。次の条件で作る。

| 項目 | 条件 | 理由 |
|---|---|---|
| 等身 | 約 5.5 頭身（いまは約 7.3）。頭は大きめで丸い | 顔と髪の画素を増やす |
| 向き | 正面、左右対称、直立 | 位置合わせと左右そろった靴・手袋のため |
| 腕 | まっすぐ、体から約 35 度離す。わきにすき間 | 袖と胴、手袋と腰が重ならない |
| 手 | 開いて力を抜く。指はそろえる | 手袋の形が単純になる |
| 脚 | まっすぐ。**股下から足先まで、左右の脚の間にすき間** | 靴・ブーツ・ズボンが左右で重ならない |
| 足 | 地面にべったり。つま先を外へ約 30 度。左右の足の間は足 1 つ分 | 靴の甲とつま先が見える。つま先立ちにしない |
| 頭 | 髪なし、顔なし（目・鼻・口なし）。耳は小さく単純 | 顔と髪は別のアイテム |
| 線と塗り | 細いこげ茶の輪郭線、影は少なめ | はみ出しが目立たない。差し替えの継ぎ目が合いやすい |
| 下着 | いまと同じ白のチューブトップとショートパンツ | — |

作り方:

1. 「アニメ」の画像を見本に、上の条件を指示文にして 2K で数枚（最大 6 枚）生成する。
2. 条件に合う 1〜2 枚に絞り、**作者に画像を見せて選んでもらう**（見た目は作者が決める）。
3. 選ばれた画像を切り抜き、1024px のキャンバスに、いまのドールと同じ余白で収める。2K の元画像も素材リポジトリの `studio/` に残す（拡大図を作るときの元にする）。
4. スタジオの既存の「ドールを追加」と同じ経路で登録し、型紙（部位の位置）を確認・手直しする。カテゴリは「アニメ」と同じ 11 個を、同じ重ね順で作る。

指示文と手順は、あとで別のドールを作るときに使えるよう、`tools/studio/` に関数とスクリプトとして残す。

### 5.2 拡大図で生成する（共通の仕組み）

いま「かお」だけがやっている「ドールの一部を正方形に切り出して拡大 → そこに描かせる → 元の位置に戻す」を、共通の仕組みにする。カテゴリの種類ごとに、型紙の部位から切り出す範囲を決める。

| カテゴリの種類 | 切り出す範囲 | 描かせる土台 | 取り出し方 |
|---|---|---|---|
| かお | 頭のまわり（いまと同じ） | 本物の頭 | いまと同じ（頭ごと「お面」として切り取る） |
| ヘアスタイル、ぼうし | 頭の上の余白から腰まで | 単色のシルエット | いまと同じ色抜き → 前髪／後ろ髪の分割 |
| くつ | すねの途中から足の下の余白まで | **本物の脚と足** | 差し替え（5.3） |
| てぶくろ | 左右それぞれ、ひじの下から指先まで。2 つを 1 枚の図に左右に並べる | **本物の腕と手** | 差し替え（5.3） |
| ソックス | ひざ上から足の下の余白まで（こちらで決めた。下の注） | 単色のシルエット | いまと同じ色抜き |
| その他（トップス、ボトムス、ドレス、インナー、アクセサリー） | 全身（いまと同じ） | 単色のシルエット | いまと同じ |

- 切り出す範囲は、作業用キャンバス（ドールのまわりに余白を足したもの。既存の `WORK_MARGIN`）の上で取る。靴底や頭より上の髪が切れないようにするため。
- 拡大図は、2K の元画像があればそこから作る（ぼやけない）。無いドール（既存の 2 体）は 1024px から拡大する。
- 髪は腰までの範囲に描かせるので、**腰より長い髪は作れない**。企画の指示に「髪は腰まで」を足す。
- この仕組みはドールを選ばない。既存の 2 体で靴や髪を作るときも、同じ道を通る。
- ソックスを拡大図にするのは、足もとの細部のため。試していないので、出来が全身方式より悪ければ全身方式に戻す（builder の判断でよい）。
- てぶくろの「左右を 1 枚に並べる」は試していない。実装の最初に本物の生成で確かめ、だめなら片手ずつ 2 枚にする（その場合だけ 1 品目 2 枚になる。作者に報告する）。

### 5.3 部位の差し替え（くつ、てぶくろ）

各部位に「切り替え線」を決める。足は足首（くるぶしの少し上）、手は手首。型紙の部位（`feet`、`handLeft`、`handRight`）から自動で決め、スタジオの型紙の画面で直せるようにする。

アイテムの画像を作るとき:

- **線より先（足先・指先側）**: 生成画像の、背景以外のすべてをアイテムにする。靴の中に見える足の甲や、手袋から出る指も、アイテムの絵の一部になる。
- **線より元（すね・前腕側）**: 生成画像が元の拡大図と**違う所だけ**をアイテムにする（ブーツの筒、長手袋）。変わっていない肌は入れない。入れると、靴下やそでの上に肌がかぶさるため。
- 線の所で、アイテムの肌の色を元のドールに合わせる（既存の `matchToReference` と同じ考え方）。

ゲームで着せたとき:

- そのアイテムを着ているあいだ、ドールの線より先を隠す。これは、いまある「hide」（アイテムごとの、ドールを隠すマスク）をそのまま使う。**ゲーム側の描画の仕組みは変えない**。
- 靴下の上に、甲の開いた靴（パンプスなど）をはくと、甲は靴の絵の肌色になる（靴下が甲だけ消える）。今回は受け入れ、作者に見てもらってから決める。

顔は、いまの方式（頭ごとお面として重ねる）がすでに差し替え式なので、そのままにする。

### 5.4 検品と指示文

- 靴の「足を完全に覆う閉じた靴だけ」という決まり（企画・生成・検品の 3 か所）を外す。差し替え式なら、甲の開いた靴も作れる。
- 靴・手袋の指示文は、「本物の脚（腕）の拡大図に、この品目をはかせる。脚（腕）は動かさない。背景は単色のまま」という形にする（2 章で使った文が元）。
- 数値の検品に、差し替え式のものを足す: 線より元の側で、元の拡大図と大きく違う画素が多すぎれば（AI が脚ごと描き直した）、作り直す。顔の `REPAINT_LIMIT` と同じ考え方。
- 靴・手袋に付けていた「手と足の拡大図を参考として 2 枚目に渡す」は、土台そのものが拡大図になるので、やめる。

### 5.5 ゲーム本体

- 変更は、版数だけの見込み。ドールの追加は一覧ファイル（manifest）だけで済む作りになっている。
- 新ドールは等身と立ち幅が違うので、ゲームの画面で、ドールの大きさ・位置・メニューとの重なりを確かめる。

### 5.6 確かめ方

- 画像処理の新しい関数（切り出す範囲、差し替えの取り出し、描き直しの検出）は、テストを先に書く。固定素材として、2 章の試行の画像（ドールのすねから下、パンプス、ブーツ）を `tools/studio/fixtures/` に置く。
- 既存のユニット・E2E・型・lint がすべて通ること。
- 本物の生成: 新ドールで、靴 5・髪 5・手袋 3・顔 3・服（トップス、ボトムス、ドレス、ソックス）各 2 を作り、ドールに着せた画像を作者に見せる。**この環境には Claude API のキーが無い**ので、品目の案と見た目の検品は、このセッションの中で人の代わりにこちらが行う（スタジオの「企画」と「見た目の検品」は、偽物ではない本物では通さない）。
- 画像生成の枚数は、ドール選びを含めて、このセッションで合計 50 枚までにする。超えそうなら作者に聞く。

### 5.7 素材リポジトリ

新ドールとその服は、素材リポジトリ `Kake-git-hub/DressUpGame-content` に入れる。このセッションからは、まだ書き込めない（リポジトリの追加が要る）。作者に、出来を見て了承をもらってから公開する。

## 7. builder に任せること

- 関数とファイルの分け方、名前。既存の `processFace.ts`・`processGenerated.ts`・`limbZones.ts`・`fillInside.ts` のうち、新しい方式で要らなくなるものの整理（既存の 2 体でも新方式を使うので、靴の内側を埋める処理などは外してよい）。
- 切り出す範囲・切り替え線の具体的な割合、描き直しの判定のしきい値（本物の画像で合わせる）。
- 型紙の画面での、切り替え線の見せ方と直し方。
- ソックス・ぼうしを拡大図にするか全身のままにするか（出来で決める）。

## 9. 結果（2026-11-19、v0.18.0）

計画: `../plans/2026-11-19-new-doll-and-part-swap.md`

**できたこと**

- 枠の計算（`src/pipeline/frames.ts`）、拡大図の描画と貼り戻し（`tools/studio/frame.ts`）、差し替え式の取り出し（`tools/studio/processSwap.ts`）、生成への組み込み（`generate.ts`・`api.ts`）、候補カードの「隠す所」（`ItemCard.tsx`）、ドールづくりの道具（`dollPrompt.ts`・`makeDoll.ts`）、本物の生成を回すスクリプト（`tryItems.ts`）。
- 作者が選んだドール（候補 2）は、取り込みまで確かめた（一時フォルダ。素材リポジトリには未登録）。

**本物の画像で確かめたこと**（生成済みの試行の画像 5 枚を、実装した処理に通した）

- パンプス・ブーツ: 警告なし。位置合わせのずれ 0。足首の継ぎ目・ドールの足の消し残りなし（最初は、足の輪郭のうすい線と、足首の細いすき間が出た。直してテストにした）。
- 髪: 青・緑の色残り 0.5% 未満。ゲームで前髪／後ろ髪に分かれて表示される。
- ゲーム本体（ビルドした版）で、試行のドールに髪と靴を着せた画面: `2026-11-19-spike/game-check.jpg`。靴をはくと足が差し替わる。ゲーム本体のコードは版数以外変えていない。

**本物の画像で見つけて直したこと**

- 頭の位置合わせ（`refineAtAnchor`）が、長い髪のとき絵を上へずらしていた（首が見えていると、ずらすほど点が増える数え方だった）。割合で見るように直した。**既存のドールの髪・帽子にも効く。**
- 手袋の図は、左右の腕がつながって 1 つの形に見えたので、あいだに背景の帯を空け、胴が写りこまないようにした。
- 画像 API が月の上限額で断ったとき、「少し待って」ではなく、上限額であることを伝える。

**確かめられていないこと**

1. **新ドール（候補 2）での本番の生成（靴 5・髪 5・手袋 3・顔 3・服 8）は、1 枚もできていない。** 最初の 4 枚を出した時点で、Gemini API が「月の上限額を超えた」と断った（HTTP 429）。使えた画像は合計 10 枚（ドール 5、靴 2、髪 1、動作確認 2）。目標（靴・髪それぞれ 5 点中 4 点以上）は未判定。
2. 手袋の「左右を 1 枚に並べる」方式は、本物の AI では未確認（偽の AI でのテストだけ）。
3. 帽子を上半身の拡大図で作る方式も、本物の AI では未確認。
4. 既存の 2 体（アニメ・リアル）での新方式の出来（やらないこと、のとおり）。
5. スタジオの画面で、差し替え式の候補のカードを実際に開いた確認（API のテストと、処理の結果の画像でだけ確かめた）。

直していない小さな指摘:

- AI が拡大図を大きくずらしたとき（7% 以上）は、ずれそのものは警告にならない（「描き直し」の警告で間接的に分かる）。
- 手袋の結果に付く位置合わせの値は、右手の分だけ（表示用の値で、処理には使わない）。
- 頭がほとんど隠れる品目（フードなど）で、頭の位置合わせが不安定になるかもしれない（未確認）。
- 高解像度の元画像が無いドールでは、生成のたびにファイルの有無を確かめ直す（少し遅いだけ）。
- 腕が体に近い既存のドールでは、手袋の内側が拡大図の端で切れることがある（新ドールは腕が離れているので起きない）。

## 11. 公開（2026-11-19）

- 作者の了承を得て、素材リポジトリに、ドール「アニメ　その２」（作者が決めた名前）と 25 点を公開した。公開サイトで、ドールを選んで着せられることを確かめた（ゲーム v0.18.1）。
- **公開後に見つけて直したこと**: ドレス 2 点（プリンセスドレス、あおいワンピース）は、手の形を直す前のドールで作っていたので、手のまわりに古い手の形の線や穴が残っていた。全身のシルエットで作る服は、ドールの形に沿って切り抜かれるためである。この 2 点を、いまのドールで作り直して差し替えた（画像 2 枚。セッション合計 42 枚）。
