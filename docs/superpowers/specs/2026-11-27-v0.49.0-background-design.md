# v0.49.0: アプリの「つくる」で、背景も作る — 設計と、できたもの

作者が決めたことは `2026-11-27-v0.49.0-background-decisions.md`（ドールごと・チケット 1 枚・クローゼットに足す・交換で渡せる）。この文書は、それをどう作ったかの記録。写真は `2026-11-27-v0.49.0/`。

## 1. できたもの

- 「つくる」の「なにを 作る？」の最後（セットのあと）に「はいけい」のタイル。絵は、そのドールで使える先頭の背景のサムネイル（無ければ 🖼️）。選ぶと、1 点の服と同じ段取り（テーマ → 絵柄 → 確かめ）で、チケット 1 枚。説明の文は足していない。
- 画面の題は「✨ つくる」。
- できた背景は、そのドールの「🖼️はいけい」の一覧の**先頭**（公開の背景の前）に出る。絵は端末の控えに入るので、一度届けば、オフラインでも選べる（服と同じ仕組み）。
- 届いた演出は「あたらしい はいけいが とどいたよ！」。背景の絵だけを見せる（ドールは重ねない）。「つかってみる」で、そのドールのゲーム画面に、その背景で移る。
- クローゼットに「はいけい」の組（服の組のあと）。開くと、名前を変える・消す、だけ（色・ならび・いちを きめる、は出さない）。
- こうかんの「えらぶ」一覧にも「はいけい」の組が出て、服と同じように出せる。背景と服、背景と背景、どちらでも入れ替えられる。もらった背景は、同じドール用。
- できなかったときは、服と同じ守りで、チケットが戻る。
- サーバーの版は 9（`SERVER_API`）。背景に要る版は `BG_API` = 9。古いサーバーにつないだアプリでは、タイルを出さない（知らせも出さない）。載せ直しは `docs/firebase-setup.md` の 2-17。

## 2. データの形（選んだものと、理由）

**背景の印は、カテゴリの ID ひとつ: `__background`（`src/cloud/wire.ts` の `BACKGROUND_CATEGORY`）。**

- **仕事（`JobDoc`）**: いままでと同じ形。品目（`candidates`）が 1 つで、その `categoryId` が `__background`。`set`・`width`・`photo` は付かない。
- **できた背景**: 服と同じ置き場（`users/{uid}/items/{id}` = `ItemDoc`）に、服と同じ形で入れる。
  - `item.category` = `__background`、`item.image` = 背景の絵（`files/background.webp`。キャンバス全体 = `box` が全面）、`item.thumb` = サムネイル（`files/background-thumb.webp`）。
  - `dollId` = 作ったドール。`hue` は 0、`fit`・`set` は無い。ID は、服と同じ `my:{仕事}-0-{回}`。
  - 絵は、長い辺 1024 の WebP（品質 85。服の絵は透明があるので可逆だが、背景は写真に近い絵なので、軽い方にした）と、192 のサムネイル。置き場のパスも服と同じ `users/{uid}/items/{id}/`。

理由:

- 一覧（`items`）・絵を取る（`itemFiles`）・消す（`deleteItem`）・交換（`swapTrade`）・引き継ぎ（`moveItem`・`drain`）・端末の控え（`sync.ts`・`library.ts`）が、**1 行も変えずに**背景にも効く。置き場の部品（メモリ・Firestore）は、変えていない。Firestore の決まり・索引・Storage の決まりも、変えていない。
- 印を 2 つ（たとえば `kind` と カテゴリ）持つと、食い違う余地ができる。`ManifestItem` には、もともとカテゴリが必ず要るので、そこを印にした。
- 生成を進める所（`runJob`）は、「絵を作って、保存する」の 2 か所だけが背景用に分かれる。受け持ち・追い越し・やり直し・払い戻し・24 時間の打ち切り、は、服と同じ道を通る。
- 前の版のアプリ（まだ更新されていない端末）が、交換で背景をもらっても、こわれない: ゲームのメニューには出ず（知らないカテゴリの服は、重ねない）、クローゼットでは「そのほか」に出て、消せる。

サーバーの細かいこと:

- `startJob`: チケットが足りるかを、AI を呼ぶ前に確かめる（服と同じ）。管理者は引かずに台帳に残す。写真は断る。テーマの幅を測る呼び出し（`planWidth`）は、しない。企画は `planBackgrounds`（1 枚。同じ名前を避けるために、その人の、そのドールの背景の名前を渡す）。
- `runJob`: `generateBackground`（絵柄は仕事の `styleId`。内容の決まりで断られたら、説明を書き直して 1 回だけ作り直す）。画像を作る前に、1 日の上限（利用者ごと・全体）を数えるのも、服と同じ。
- `updateItem`: 背景に、色（`hue`）・はじめの位置（`fit`）を頼まれても、**変えずに、そのまま返す**（名前は変わる）。断る（refused）にしなかったのは、前の版のアプリが、背景を「そのほか」の服として開いて色を動かしたとき、「この ふくは、もう ありません」と出て一覧から消えたように見えるのを避けるため。

## 3. わざと、していないこと

- セットに背景を入れる（作者の決めたことに無い）。
- 背景の色を変える・ならびを変える画面（サーバーの `orderItems` は、背景にも効くが、画面には出していない）。
- 写真から背景を作る。
- 全部のドールで使える背景（作者が「ドールごと」と決めた）。
- 背景を消した・交換で渡したときに、覚えている「選んでいる背景」を消し直すこと（ゲームは、見つからない背景を「背景なし」として描く。次に開いたときも同じ）。
- ドールを選ぶ段の題「どの子の 服を作る？」は、そのまま（背景のときも同じ文）。

## 4. 確かめたこと・確かめられていないこと

確かめたこと（どれも、偽物の AI・メモリの置き場・偽物の裏側・エミュレーター）:

- サーバーの単体テスト `tools/cloud/background.test.ts`（チケットは 1 回だけ引く・できなければ 1 回だけ戻る・足りないときは AI を呼ばない・取り引きのやり直し・同時の呼び出し・追い越し・一覧・名前・消すと絵も消える・交換（背景と服、背景と背景）・引き継ぎ・色や位置を頼まれても変えない）。
- アプリの単体テスト `src/tests/background.test.tsx`、E2E `e2e/background.spec.ts`（タイル・古いサーバーで出ない・作る・届く・ゲームで選ぶ・オフライン・クローゼット・消しても描ける・交換・スマホの縦）。
- エミュレーター（`functions/test/callable.emu.ts`・`trade.emu.ts`）: 本物と同じ関数・Firestore・Storage のまねの上で、背景を作って、絵を取り、名前を変え、消す。背景と服の入れ替え。

**確かめられていないこと:**

- **本物の画像生成は、1 枚も試していない**（作者の費用。使う前に聞く決まり）。`generateBackground` と `planBackgrounds` は、PC のスタジオで使ってきたものを、そのまま呼んでいる。アプリの絵柄（`styleId`）の文を背景に渡したときの出来・「まんなかを空ける」の効き具合は、見ていない。
- **本物の Firebase（Firestore・Storage・列）では、動かしていない。** 背景の絵（1024 の WebP）を、関数の返事（base64）で受け取るときの大きさ・待ち時間も、測っていない。
- 実機（iPad・スマホ）では、試していない。写真は、PC のブラウザを、スマホの大きさにして撮った。
- 前の版のアプリが背景をもらったときの見え方（2 章の最後）は、コードを読んで確かめただけで、前の版を動かしてはいない。
