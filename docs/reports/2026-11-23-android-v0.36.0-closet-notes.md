# Android のスマホ、v0.36.0: クローゼットに検品結果は要らない

- 報告: GitHub の Issue 7（2026-11-23、作者）。「クローゼットには検品結果表示不要。」
- 端末: Android 10 の Chrome から入れたホーム画面のアプリ（`standalone: true`、411×844、画素の細かさ 2.625）。

## 分かったこと

1. **依頼**: クローゼットの服 1 点の画面に、検品で気づいたこと（`notes`。「注意あり」の服の注意の文）が出ていた。段階 ① の設計（6.1 の 7）で「小さく出す」と決めた所。作者の指示で、クローゼットからは外す（v0.36.1）。届いたときの演出と、「つくる」の結果のカードには、前のとおり出る（Issue は、クローゼットだけを指している）。サーバーの中身は変えていない（`notes` は、持ったまま）。
2. **きろくの「WebGLコンテキストがロストしました」は、落ちたのではなかった**。この報告には 4 回出ているが、どれも「ホームへ戻った」ときのもの:
   - ホームへ戻ると、キャンバスを片付ける（`AvatarCanvas` が外れて `PixiEngine.destroy`）。そのとき Pixi が、描画の土台を自分で手放す（`loseContext`）ので、「落ちた」の知らせが来る。
   - 根拠: どの回も、直前に Pixi の片付けの警告（`A Texture managed by Assets was destroyed…`）があり、あとに「戻った」（`gl restored`）が無く、ドールから描き直している（`doll` の行）。最後の 1 回のあとに報告を出していて、そのとき `gl: no canvas`（キャンバスが無い = ホームにいる）。
   - こちら（Chromium）で、ホームへ戻るだけで同じ 2 行が出ることを確かめた。
   - 直し（v0.36.1）: 片付けのときは、警告にせず `gl closed` と残す。これからは、「WebGLコンテキストがロストしました」は、本当に落ちたときだけ。
3. **描画は、落ちていない**。服を 6 点まで着せて、1 回の描き直しは 0.001〜0.06 秒（`ms=1`〜`ms=62`）。

## まだ分からないこと

- v0.36.0 の縦画面（服の絵の大きさ・色の帯・枠とつまみ）の手ざわりは、この報告には書かれていない。
- Pixi の片付けの警告（`A Texture managed by Assets was destroyed instead of unloaded!`）は残る（害は無い。ホームへ戻るたびに 1 行）。
