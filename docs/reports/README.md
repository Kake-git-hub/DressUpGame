# 実機の記録・不具合の報告

作者の端末（iPad など）でしか分からないことを、ここに残す。

## 作者が報告する方法（v0.36.0 から）

1. アプリの右上の版数を 5 回続けて押し、あいことば `log` を入れる（きろくの画面が出る）。
2. 何が起きたかを 1 行書いて（書かなくてもよい）、「GitHub に ほうこくする」を押す。
3. 開いた GitHub の画面で「Submit new issue」を押す（GitHub にログインしていること。最初の 1 回だけ、ログインを聞かれることがある）。

報告は、このリポジトリの Issue（題が `[きろく] v… …`）として残る。**このリポジトリは公開なので、Issue も、だれでも読める。** きろくに入るのは、端末の種類・画面の大きさ・描画の状態・警告とエラー・着せた服のカテゴリだけ（名前・アカウント・作った服の絵は入らない）。

## 開発の側が読む方法

- GitHub の Issue の一覧から、題が `[きろく]` で始まるものを読む（クラウドのセッションでは、GitHub の道具の `list_issues` → `issue_read`）。
- 読んだら、分かったことと一緒に、このフォルダに `日付-端末-版-ひとこと.md` として写す（Issue は、片付いたら閉じてよい）。
- きろくの行の読み方: `src/services/diag.ts`（仕組み）、`src/engine/PixiEngine.ts` の `diag.note`（`doll`・`clothes` の行）、`src/App.tsx` の `readGl`（`gl:` の行。`painted` は、キャンバスの 9×9 の点のうち、絵がある点の数）。
