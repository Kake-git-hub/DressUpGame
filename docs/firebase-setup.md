# Firebase の用意（作者向けの手順）

アプリの中のスタジオ（段階 E。設計書 `docs/superpowers/specs/2026-11-20-app-studio-portrait-sets-design.md` の 8 章）を動かすための準備です。
「1. 先にやること」は済んでいます（2026-11-20）。**次は「2. サーバーを載せる」です。**

画面の言葉は、Firebase の管理画面（日本語）のものです。変わっていることがあるので、見つからないときは教えてください。

## 1. 先にやること（15〜20 分）

### 1-1. プロジェクトを作る

1. https://console.firebase.google.com/ を開き、Google のアカウントでログインする。
2. 「プロジェクトを作成」（または「プロジェクトを追加」）を押す。
3. 名前を付ける（例: `dressup-game`）。Google アナリティクスは「使わない」でよい。

### 1-2. 料金プランを Blaze（従量制）に切り替える

サーバー側の処理（Cloud Functions）と、画像の置き場（Cloud Storage）は、Blaze でしか使えません。

1. 管理画面の左下の「アップグレード」（または「プランを変更」）から **Blaze** を選ぶ。
2. 請求先（クレジットカード）を登録する。

Blaze にも無料枠があります（サーバー側の処理は、月 200 万回の呼び出しまで無料）。使い始めの規模なら、Firebase 自体の料金はほぼ 0 円の見込みです。**かかるのは、今までどおり Gemini の画像代です。**

### 1-3. 予算の知らせを設定する（使いすぎに気づくため）

1. 管理画面の「使用量と請求額」→「詳細と設定」→「予算とアラート」（Google Cloud の画面に移ります）。
2. 「予算を作成」で、月の金額（例: 1,000 円）を決める。50%・90%・100% でメールが来るようにする。

**これは知らせるだけで、自動では止まりません。** 生成の枚数は、こちらで作る「チケット」と「1 日の上限」で止めます。

### 1-4. 3 つの機能を有効にする

| 機能 | 手順 |
|---|---|
| Authentication | 「構築」→「Authentication」→「始める」→「ログイン方法」→「匿名」を有効にする |
| Firestore Database | 「構築」→「Firestore Database」→「データベースを作成」→ 場所は **asia-northeast1（東京）** →「本番環境モード」で開始 |
| Storage | 「構築」→「Storage」→「始める」→「本番環境モード」→ 場所は **asia-northeast1（東京）** |

場所は、あとから変えられません。Storage の「いつでも無料」の枠は米国の場所だけですが、東京でも、服の絵の量（1 点 100KB ほど）なら、月に数円以下の見込みです。

### 1-5. ウェブアプリを登録して、設定の値をこちらに知らせる

1. 「プロジェクトの設定」（歯車）→「全般」→「マイアプリ」→ ウェブのアイコン（`</>`）。
2. ニックネームを付ける（例: `dressup-web`）。「Firebase Hosting も設定する」は**付けない**。
3. 表示される `firebaseConfig`（`apiKey`・`authDomain`・`projectId`・`storageBucket`・`messagingSenderId`・`appId`）を、そのままコピーして、こちらに貼ってください。

**この値は、公開してよい値です**（アプリの中に書くもので、Gemini のキーとは別物です。ほかの人のデータを読めないようにするのは、こちらで書く「決まり」と、サーバー側の処理です）。

## 2. サーバーを載せる（v0.27.0 から。PC で 15〜20 分）

スタジオを動かしている PC で行います。**1 回やれば、あとはアプリを開くだけ**です（サーバー側の中身を直したときだけ、2-4 をもう一度）。

### 2-1. 最新にする

スタジオを動かしていたら、先に閉じます。`DressUpGame` のフォルダで:

```bash
git pull
```

```bash
npm ci
```

```bash
node -v
```

最後の行で `v22` 以上（例: `v22.11.0`）が出れば大丈夫です。`v20` 以下のときは、https://nodejs.org/ から「LTS」を入れ直してください。

### 2-2. Firebase にログインする

```bash
npm run firebase:login
```

ブラウザが開くので、Firebase のプロジェクトを作ったのと同じ Google のアカウントでログインします（最初に「使い方の情報を送ってよいか」と聞かれたら、どちらでもかまいません）。

### 2-3. Gemini のキーを、サーバーの「秘密の値」に入れる

PC の `.env.local` に書いてあるのと同じキーを貼り付けます（貼り付けても、画面には出ません。Enter で確定）。

```bash
npm run firebase:key
```

**キーは、アプリには入りません。** サーバーの中だけで使います。

### 2-4. サーバー側の処理と、決まりを載せる

```bash
npm run firebase:deploy
```

- 3〜5 分かかります。最後に `Deploy complete!` と出れば成功です。
- 初めてのとき、「コンテナのイメージを何日残すか」（cleanup policy）を聞かれたら、そのまま Enter（1 日）でかまいません。
- 途中で「API を有効にする」と出たら、そのまま進めてください（自動で有効になります）。**有効にした直後は失敗することがあります。そのときは、1〜2 分待って、同じコマンドをもう一度**実行してください。
- うまくいかないときは、出た文字をそのままコピーして、こちらに貼ってください。

### 2-5. アプリで開いて、自分を「管理者」にする

1. iPad（または PC のブラウザ）で `https://kake-git-hub.github.io/DressUpGame/?studio=1` を開く。ホーム画面に置いたアプリでは、右上の版数を 5 回続けて押し、あいことば `studio` を入れる。
2. 「✨」→ 保護者の確認 →「服を作る」の画面のいちばん下に、**利用者コード**（8 文字）が出ます。これを控えます。
   - ここで「サーバーから返事がありません」と出るときは、2-4 がうまくいっていません。2-8 を見てください。
3. Firebase の管理画面 →「Firestore Database」→「コレクションを開始」:
   - コレクション ID: `system`
   - ドキュメント ID: `config`
   - フィールド: `adminCodes`、タイプ「string」、値に利用者コード（複数なら、カンマで区切る）
4. 1 分ほど待って、アプリの「✨」を開き直すと、右上が「管理者（チケットの制限なし）」になります。
5. **最初は、1 点だけ**（たとえば「トップス」で、テーマ「うみ」）作ってみてください。1 分ほどで、ドールに着せた絵が出れば成功です。うまくいったら、セットも試してください。

同じ `config` に、数（number）のフィールドを足すと、上限を変えられます（無ければ、かっこの中の値）。

| フィールド | 意味 |
|---|---|
| `imagesPerDay` | サーバー全体で、1 日に作る画像の上限（100 枚）。**`0` にすると、だれも作れなくなります（急いで止めたいとき）** |
| `imagesPerUserPerDay` | 利用者 1 人が、1 日に作る画像の上限（30 枚）。管理者にはかかりません |

1 日の区切りは、日本の朝 9 時です。

### 2-6. ほかの人にチケットを配る（作者用の画面ができるまでの、手作業のやり方）

作者用の画面（段階 E4）ができるまでは、Firebase の管理画面で直接書き換えます。

1. 相手に、アプリの「✨」の画面のいちばん下の**利用者コード**を教えてもらう。
2. 「Firestore Database」→ `userCodes` → 相手の利用者コードの行 → `uid` の値を控える。
3. `users` → その `uid` の行 → `tickets` の数を書き換える（服 1 点につき 1 枚）。**タイプは「number」のまま**にしてください（文字にすると、0 枚として扱われます）。

### 2-7. 費用の目安

- 服 1 点につき、Gemini の画像を 1〜2 枚作ります（うまくできなかったときに、1 回だけ作り直します）。
- **できなかった服のチケットは自動で戻りますが、作った画像の代金はかかります**（そのために、1 人あたり 1 日 30 枚の上限を付けています）。
- チケットが足りない人の呼び出しでは、AI を使いません。

### 2-8. うまくいかないとき

- サーバーの記録を見る（最後の 60 行）。出た文字を、そのままこちらに貼ってください。

```bash
npm run firebase:logs
```

- アプリに「サーバーから返事がありません」と出る: サーバーが載っていないか、起動に失敗しています。2-4 をもう一度実行して、`Deploy complete!` まで行くか見てください。
- 急いで止めたい: `system/config` の `imagesPerDay` を `0` にします（1 分ほどで効きます）。

## 3. 知っておいてほしいこと

- **Gemini の利用の決まり（年齢）**: Gemini API は、18 歳未満に向けたアプリの一部として使うことを禁じています。そのため、「つくる」は保護者（大人）が使う画面として分け、入口で確かめます。この分け方で足りるかは、販売を始める前に、Google への問い合わせか専門家の確認を取ってください（設計書 8.6）。
- **匿名の利用者**: アプリのデータを消す・ホーム画面のアプリを消すと、別の利用者になります（チケットと服を引き継げません）。販売の前に、Google か Apple のログインとの結び付けを足します（段階 F）。それまでは、作者が配り直せます。
- **費用の見張り**: 最初のうちは、月に 1 回、「使用量と請求額」を見てください。
