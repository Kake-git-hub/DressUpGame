# Firebase の用意（作者向けの手順）

アプリの中のスタジオ（段階 E。設計書 `docs/superpowers/specs/2026-11-20-app-studio-portrait-sets-design.md` の 8 章）を動かすための準備です。
「1. 先にやること」は済んでいます（2026-11-20）。**次は「2. サーバーを載せる」です。**

画面の言葉は、Firebase の管理画面（日本語）のものです。変わっていることがあるので、見つからないときは教えてください。

## 1. 先にやること（15〜20 分）

### 1-1. プロジェクトを作る

1. https://console.firebase.google.com/ を開き、Google のアカウントでログインする。
2. 「プロジェクトを作成」（または「プロジェクトを追加」）を押す。
3. 名前を付ける（例: `dressup-game`）。Google アナリティクスは「使わない」でよい。

### 1-2. 料金プランを Blaze（従量制）に切り替える

サーバー側の処理（Cloud Functions）と、画像の置き場（Cloud Storage）は、Blaze でしか使えません。

1. 管理画面の左下の「アップグレード」（または「プランを変更」）から **Blaze** を選ぶ。
2. 請求先（クレジットカード）を登録する。

Blaze にも無料枠があります（サーバー側の処理は、月 200 万回の呼び出しまで無料）。使い始めの規模なら、Firebase 自体の料金はほぼ 0 円の見込みです。**かかるのは、今までどおり Gemini の画像代です。**

### 1-3. 予算の知らせを設定する（使いすぎに気づくため）

1. 管理画面の「使用量と請求額」→「詳細と設定」→「予算とアラート」（Google Cloud の画面に移ります）。
2. 「予算を作成」で、月の金額（例: 1,000 円）を決める。50%・90%・100% でメールが来るようにする。

**これは知らせるだけで、自動では止まりません。** 生成の枚数は、こちらで作る「チケット」と「1 日の上限」で止めます。

### 1-4. 3 つの機能を有効にする

| 機能 | 手順 |
|---|---|
| Authentication | 「構築」→「Authentication」→「始める」→「ログイン方法」→「匿名」を有効にする |
| Firestore Database | 「構築」→「Firestore Database」→「データベースを作成」→ 場所は **asia-northeast1（東京）** →「本番環境モード」で開始 |
| Storage | 「構築」→「Storage」→「始める」→「本番環境モード」→ 場所は **asia-northeast1（東京）** |

場所は、あとから変えられません。Storage の「いつでも無料」の枠は米国の場所だけですが、東京でも、服の絵の量（1 点 100KB ほど）なら、月に数円以下の見込みです。

### 1-5. ウェブアプリを登録して、設定の値をこちらに知らせる

1. 「プロジェクトの設定」（歯車）→「全般」→「マイアプリ」→ ウェブのアイコン（`</>`）。
2. ニックネームを付ける（例: `dressup-web`）。「Firebase Hosting も設定する」は**付けない**。
3. 表示される `firebaseConfig`（`apiKey`・`authDomain`・`projectId`・`storageBucket`・`messagingSenderId`・`appId`）を、そのままコピーして、こちらに貼ってください。

**この値は、公開してよい値です**（アプリの中に書くもので、Gemini のキーとは別物です。ほかの人のデータを読めないようにするのは、こちらで書く「決まり」と、サーバー側の処理です）。

## 2. サーバーを載せる（v0.27.0 から。PC で 15〜20 分）

スタジオを動かしている PC で行います。**1 回やれば、あとはアプリを開くだけ**です（サーバー側の中身を直したときだけ、2-4 をもう一度）。

### 2-1. 最新にする

スタジオを動かしていたら、先に閉じます。`DressUpGame` のフォルダで:

```bash
git pull
```

```bash
npm ci
```

```bash
node -v
```

最後の行で `v22` 以上（例: `v22.11.0`）が出れば大丈夫です。`v20` 以下のときは、https://nodejs.org/ から「LTS」を入れ直してください。

### 2-2. Firebase にログインする

```bash
npm run firebase:login
```

ブラウザが開くので、Firebase のプロジェクトを作ったのと同じ Google のアカウントでログインします（最初に「使い方の情報を送ってよいか」と聞かれたら、どちらでもかまいません）。

### 2-3. Gemini のキーを、サーバーの「秘密の値」に入れる

PC の `.env.local` に書いてあるのと同じキーを貼り付けます（貼り付けても、画面には出ません。Enter で確定）。

```bash
npm run firebase:key
```

**キーは、アプリには入りません。** サーバーの中だけで使います。

### 2-4. サーバー側の処理と、決まりを載せる

```bash
npm run firebase:deploy
```

- 3〜5 分かかります。最後に `Deploy complete!` と出れば成功です。
- 初めてのとき、「コンテナのイメージを何日残すか」（cleanup policy）を聞かれたら、そのまま Enter（1 日）でかまいません。
- 途中で「API を有効にする」と出たら、そのまま進めてください（自動で有効になります）。**有効にした直後は失敗することがあります。そのときは、1〜2 分待って、同じコマンドをもう一度**実行してください。
- うまくいかないときは、出た文字をそのままコピーして、こちらに貼ってください。

### 2-5. アプリで開いて、自分を「管理者」にする

1. iPad（または PC のブラウザ）で `https://kake-git-hub.github.io/DressUpGame/?studio=1` を開く。ホーム画面に置いたアプリでは、右上の版数を 5 回続けて押し、あいことば `studio` を入れる。
2. ホームの「つくる」（v0.34.0 までは、ゲームの画面の「✨」→ 保護者の確認）→「服を作る」の画面のいちばん下に、**利用者コード**（8 文字）が出ます。これを控えます。
   - ここで「サーバーから返事がありません」と出るときは、2-4 がうまくいっていません。2-8 を見てください。
3. Firebase の管理画面 →「Firestore Database」→「コレクションを開始」:
   - コレクション ID: `system`
   - ドキュメント ID: `config`
   - フィールド: `adminCodes`、タイプ「string」、値に利用者コード（複数なら、カンマで区切る）
4. 1 分ほど待って、「つくる」を開き直すと、右上が「管理者（チケットの制限なし）」になります。
5. **最初は、1 点だけ**（たとえば「トップス」で、テーマ「うみ」）作ってみてください。1 分ほどで、「あたらしい ふくが とどいたよ！」と出れば成功です。うまくいったら、セットも試してください。

同じ `config` に、数（number）のフィールドを足すと、上限を変えられます（無ければ、かっこの中の値）。

| フィールド | 意味 |
|---|---|
| `imagesPerDay` | サーバー全体で、1 日に作る画像の上限（100 枚）。**`0` にすると、だれも作れなくなります（急いで止めたいとき）** |
| `imagesPerUserPerDay` | 利用者 1 人が、1 日に作る画像の上限（30 枚）。管理者にはかかりません |

1 日の区切りは、日本の朝 9 時です。

### 2-6. ほかの人にチケットを配る（作者用の画面ができるまでの、手作業のやり方）

**v0.42.0 からは、アプリの中で配れます（2-13）。** 下は、載せ直す前の手作業のやり方です。

作者用の画面（段階 E4）ができるまでは、Firebase の管理画面で直接書き換えます。

1. 相手に、「つくる」の画面のいちばん下の**利用者コード**を教えてもらう。
2. 「Firestore Database」→ `userCodes` → 相手の利用者コードの行 → `uid` の値を控える。
3. `users` → その `uid` の行 → `tickets` の数を書き換える（服 1 点につき 1 枚）。**タイプは「number」のまま**にしてください（文字にすると、0 枚として扱われます）。

### 2-7. 費用の目安

- 服 1 点につき、Gemini の画像を 1〜2 枚作ります（うまくできなかったときに、1 回だけ作り直します）。
- **できなかった服のチケットは自動で戻りますが、作った画像の代金はかかります**（そのために、1 人あたり 1 日 30 枚の上限を付けています）。
- チケットが足りない人の呼び出しでは、AI を使いません。

### 2-8. うまくいかないとき

- サーバーの記録を見る（最後の 60 行）。出た文字を、そのままこちらに貼ってください。

```bash
npm run firebase:logs
```

- アプリに「サーバーから返事がありません」と出る: サーバーが載っていないか、起動に失敗しています。2-4 をもう一度実行して、`Deploy complete!` まで行くか見てください。
- 急いで止めたい: `system/config` の `imagesPerDay` を `0` にします（1 分ほどで効きます）。

## 2-9. v0.35.0 の載せ直し（PC で 5〜10 分）

v0.35.0 から、生成は、サーバーの「順番待ちの列」（Cloud Tasks）が進めます。アプリを閉じても、電源を切っても、最後まで作り、できた服は自動でクローゼットに入ります。**サーバーを載せ直すまで、新しいアプリの「つくる」は「サーバーが古い版です」と出て、作れません**（ゲームは、いつもどおり遊べます）。

```bash
cd DressUpGame
git checkout main
git pull
npm ci
npm run firebase:deploy
```

途中で聞かれること:

| 聞かれること | 答え |
|---|---|
| API（Cloud Tasks・Cloud Scheduler など）を有効にしますか | `y`（はい） |
| 古い関数 `studioRun` を消しますか（`Would you like to proceed with deletion?`） | `y`（はい。もう使いません） |

`Deploy complete!` と出たら、載っています。関数は 3 つになります: `studio`（アプリからの呼び出し）・`studioWork`（列が呼ぶ。生成を進める）・`studioSweep`（1 時間に 1 回の見回り）。

**載せたあとに、確かめてほしいこと**（こちらでは、本物の列を動かせていません）:

1. アプリのホーム →「つくる」で、1 点（たとえば「トップス」、テーマ「うみ」）注文する。
2. 「チョキン！」のあと「OK」を押して、**すぐアプリを閉じる**。
3. 1〜2 分待って、アプリを開く。「あたらしい ふくが とどいたよ！」と出て、クローゼットに入っていれば成功です。
4. うまくいったら、セット（3 点くらい）でも同じことを試してください。

**届かないとき**: 次の 2 つを、こちらに送ってください。その場合も、チケットは 24 時間ほどで自動で戻ります（1 時間に 1 回の見回りが、終わらない仕事を打ち切って払い戻します）。

1. `npm run firebase:logs` の文字（そのまま貼る）。「仕事を列に入れられませんでした」と出ていれば、列に入れる権限が足りていません。
2. 何も出ていないときは、列には入ったのに、列が関数を呼べていない見込みです。https://console.cloud.google.com/cloudtasks を開き、プロジェクト `dressup-game-89f6e` の列 `studioWork` を押して、**画面の写真**をください（「タスク」の数と、「前回の試行」の欄の文字が見たいです）。

こちらで見当を付けている原因（どれも、管理画面で権限を足せば直ります。手順は、文字と写真を見てお伝えします）: 関数を動かしている利用者（サービス アカウント）に、(a) 列に仕事を入れる権限（Cloud Tasks へのデータ追加）、(b) 自分自身として動く権限（サービス アカウント ユーザー）、(c) 関数 `studioWork` を呼ぶ権限（Cloud Run 起動元）のどれかが足りない。

**利用者が増えて、待ち時間が長くなったら**: `functions/src/index.ts` の `WORKERS`（同時に進める仕事の数。いまは 3）を大きくして、載せ直します。1 日の上限（`imagesPerDay`）も、合わせて見直してください。

## 2-10. Google のログインを有効にする（v0.37.0 から。ブラウザで 5〜10 分。PC でなくてもよい）

v0.37.0 から、「つくる」のいちばん下に「アカウント」の欄があり、Google のアカウントでログインできます（ためしの版。設計書 `docs/superpowers/specs/2026-11-23-login-design.md`）。**サーバーの載せ直しは、要りません。** 次の 3 つの設定だけです。設定が済むまでは、ログインを押しても「Google のログインの準備が、まだできていません」と出るだけで、ほかは、いつもどおり使えます。

### 1. Google のログインを有効にする

1. https://console.firebase.google.com/ → プロジェクト `dressup-game-89f6e` →「構築」→「Authentication」→「ログイン方法」。
2. 「新しいプロバイダを追加」→「Google」→「有効にする」。
3. 「プロジェクトのサポートメール」に、自分のメールアドレスを選ぶ →「保存」。

（「プロジェクトの公開名」を聞かれたら、`きせかえ` などで構いません。Google のログインの画面に出る名前です。）

### 2. アプリの場所を、許可する（方法 1 に要ります。方法 2 にも要る見込みです）

1. 同じ「Authentication」→「設定」→「承認済みドメイン」→「ドメインを追加」。
2. `kake-git-hub.github.io` と入れて「追加」。

### 3. 戻り先の URL を、登録する（方法 2 に要ります）

1. https://console.cloud.google.com/apis/credentials?project=dressup-game-89f6e を開く（Google Cloud の画面です。Firebase と同じ Google のアカウントで入ります）。
2. 「OAuth 2.0 クライアント ID」の一覧の **「Web client (auto created by Google Service)」** を押す。
3. 「承認済みのリダイレクト URI」の「URI を追加」→ 次の文字を、そのまま入れる（最後の `/` まで）:

   ```
   https://kake-git-hub.github.io/DressUpGame/
   ```

4. 「保存」。**効くまで、数分〜数時間かかることがあります。**

「Web client (auto created by Google Service)」が見つからないときは、1 の「Google を有効にする」が、まだ済んでいません（有効にすると、自動で作られます）。

### 4. 試して、報告する

iPad とスマホ（ホーム画面のアプリ）と、できれば PC のブラウザで:

1. 「つくる」→ いちばん下の「アカウント」→「Google でログイン（方法 1: 小さい窓）」。
2. うまくいったら、「ログアウト」して、「Google でログイン（方法 2: 画面を移る）」。うまくいかなかったら、そのまま方法 2 を試す。
3. どちらの結果でも、版数を 5 回押して `log` →「GitHub に ほうこくする」（何が起きたかを 1 行。例: 「方法 1 は 窓が出たが 戻らない。方法 2 は できた」）。

知っておいてほしいこと:

- **1 台め**は、いまのチケットと服が、そのままアカウントのものになります（利用者コードも、管理者の印も、変わりません）。
- **2 台め**は、その端末にチケットか服があると、ためしの版では「次の版でできるようになります」と出ます（それで正しい動きです。その文が出れば、Google の画面が開いて、戻って来られた、と分かります）。チケットも服も無い端末なら、そのままアカウントに入れます。
- 「ログアウト」すると、その端末では、チケットと服が見えなくなります。**無くなりません**（同じ Google でログインすると、戻ります）。
- 方法 2 で、Google の画面に `redirect_uri_mismatch`（または「このアプリのリクエストは無効です」）と出たら、3 の登録が、まだ効いていません。しばらく待って、もう一度試してください。それでも出るときは、その画面の写真をください。
- きろくには、メールアドレスは入りません。

## 2-11. v0.38.0 の載せ直し（2 台めの端末を、アカウントに合わせる。PC で 5〜10 分）

v0.38.0 から、ログインのボタンは「Google でログイン」1 つです（うまくいかないときのために、下に小さく「小さい窓でログイン」があります）。そして、**2 台めの端末**（チケットか服がある端末）で、もう使っている Google のアカウントを選ぶと、**聞かずに、その端末のチケットと服を、アカウントに合わせて**ログインします。

合わせるには、サーバーの載せ直しが要ります。**載せ直すまでは、2 台めを合わせることだけが、できません**（「サーバーが古い版のため、まだ合わせられません」と出て、何も変わりません）。「つくる」・クローゼット・1 台めのログイン・ログアウトは、載せ直す前でも、いままでどおり動きます。

### 1. 載せ直す

```bash
cd DressUpGame
```

```bash
git checkout main
```

```bash
git pull
```

```bash
npm ci
```

```bash
npm run firebase:deploy
```

`Deploy complete!` と出たら、載っています。途中で聞かれたら、2-9 と同じく `y`（はい）です。

### 2. 2 台めの端末で試す

1. 2 台めの端末（スマホなど。チケットか服がある）で、「つくる」→ いちばん下の「アカウント」→「Google でログイン」。
2. Google の画面で、1 台めと同じアカウントを選ぶ。画面が 1〜2 回、切り替わります（そのアカウントが、もう使われていると分かったあと、合わせる準備をして、入り直すためです）。
3. ホームに「Google のアカウントでログインしました。この端末のチケットと服を、アカウントに合わせました」と出たら、成功です。チケットの数（2 台の合計）と、クローゼット（両方の服）を見てください。1 台めの端末でも、開き直すと、同じチケットと服が出ます。
4. 版数を 5 回押して `log` →「GitHub に ほうこくする」。きろくの「--- ログイン ---」の所に、ログインの行が、読み込み直しをはさんでも残るようになりました。

「…インターネットにつながったときに、合わせます」と出たときは、ログインはできていて、合わせるのだけが、まだです。アプリを開き直すと、合わさります（それまで、その端末の服は、端末で着られるままです）。

### 3. 管理者の端末を合わせたとき

管理者の印は、利用者コードに付いています。**管理者の端末を、ほかのアカウントに合わせると、その端末は、管理者でなくなります**（知らせに「この端末は管理者でしたが…」と出ます。チケットと服は、合わさっています）。管理者に戻すには:

1. その端末の「つくる」のいちばん下の「利用者コード」を見る（合わせたあとの、アカウントの利用者コードです）。
2. Firebase の管理画面 →「Firestore Database」→ `system` → `config` → `adminCodes` を、その利用者コードに書き換える（前のコードは、もう使いません。2-5 と同じ場所です）。
3. 1 分ほど待って、アプリを開き直す。

1 台めにログインした端末が管理者の端末なら、何もしなくて大丈夫です（利用者コードは、変わっていません）。

## 2-12. v0.41.0 の載せ直し（交換。PC で 5〜10 分）

v0.41.0 から、クローゼットに「こうかん」が付きました。会ったときだけ、友だちと服を 1 点ずつ入れ替えられます（片方が QR コードを出し、もう片方がカメラで読みます）。

交換には、サーバーの載せ直しが要ります。**載せ直すまでは、こうかんの画面に「こうかんは まだ つかえません（サーバーが ふるい はんです）」と出て、交換だけができません**（カメラも開きません）。「つくる」・クローゼット・ログインなどは、載せ直す前でも、いままでどおり動きます。

### 1. 載せ直す

```bash
cd DressUpGame
```

```bash
git checkout main
```

```bash
git pull
```

```bash
npm ci
```

```bash
npm run firebase:deploy
```

`Deploy complete!` と出たら、載っています。途中で聞かれたら、2-9 と同じく `y`（はい）です。

**v0.43.0 以降を載せるときの注意**: 載せ直すとき、`STRIPE_SECRET_KEY` と `STRIPE_WEBHOOK_SECRET` の 2 つの秘密の値を聞かれる（無いと載せられない）ことがあります。Stripe のアカウントがまだ無ければ、2 つとも `pending` と入れてください（2-14 の 2 を見る）。買う機能は閉じたままです。

### 2. 2 台で試す

1. 2 台の端末（どちらも「つくる」を教えてあって、服が 1 点以上ある）で、クローゼット →「こうかん」。
2. 片方で「QRコードを だす」→ 服を選ぶ → QR コードが出ます。もう片方で「QRコードを よむ」→ カメラの許可を「許可」→ 相手の画面の QR コードを写す → 服を選ぶ。

### 9. 困ったとき

- 記録（`npm run firebase:logs`）に **「【要手当て】」** が出たら、**お金は払われたのに、チケットが付いていません**（購入の記録が無く、直せなかった、または利用者がいない）。Stripe の管理画面で、その支払い（記録の `session` の番号で探す）を確かめて、
  - 利用者が分かるなら、2-13 の「配る」で、チケットを足す（無料のチケットとして足されます）。
  - 分からない・直せないなら、Stripe の管理画面から**返金**する。
- 返金・カード会社からの取り消し（チャージバック）は、Stripe が知らせてくれて、買ったチケットが、返金した割合の分だけ減ります（取り消しは、そのパックの全部）。使ってしまった分は、残っている分から取り戻せるだけです。管理画面での返金のあと、アプリの枚数が変わるまで、少し待ってください。
- `checkout` が「いまは かえません」と出る: 秘密の値が入っていない、`packs` が空、または `salesOpen` が false で管理者の端末でない、のどれかです。
- 知らせが届かない: Stripe の「Webhook」の画面で、送り先ごとに、送った知らせと、返事（200 か、エラーか）が見えます。400 は署名の鍵（`STRIPE_WEBHOOK_SECRET`）が違います。

**まだ確かめていないこと:** 本物の Stripe（試し用の鍵 `sk_test_` を含む）への通信は、こちらでは 1 回もできていません（テストは、にせの Stripe だけです）。支払い → 知らせ → チケット、返金の通しは、上の 6 で初めて確かめることになります。
